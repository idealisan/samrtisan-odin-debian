# 二、刷入指南（从原生 fastboot 一路到 SSH 可用）

驱动器是 `flash/flash-all.sh`，阶段编号 `00`→`90`。**任何阶段失败都可以
`--from <阶段>` 单独重跑**，不必从头再来。

```sh
flash/flash-all.sh                 # 从头跑（00 → 90）
flash/flash-all.sh --from 40       # 从刷 userdata 那步继续
flash/flash-all.sh --dry-run       # 只打印将执行的动作，不真刷
flash/flash-all.sh --help          # 打印脚本头部的用法说明
```

公共函数在 `flash/lib/common.sh`（日志、重试、超时、SSH / fastboot 封装）。

---

## ⚠️ 零、先备份（刷 userdata 会清空手机全部数据）

**刷 userdata 会清空设备上的全部数据**（照片 / 应用 / 聊天记录）。本包不触碰
aboot / modem / persist 等分区，但 userdata 是要被整体覆盖的。

备份走 `flash/stages/10-backup.sh`：

```sh
flash/stages/10-backup.sh              # 在手机上打包（后台跑，只轮询大小）
flash/stages/10-backup.sh --status     # 只看进度，不启动新任务
flash/stages/10-backup.sh --fetch      # 把已生成的备份包拉回主机
```

备份落在设备的 `/root/odin-backup/rootfs-full.tar`，拉回到本机的
`evidence/live-device-backup/rootfs-full.tar`（可用第二个参数改落点）。

### 为什么是"手机上打包 + HTTP 拉回"

最初写成 `ssh 设备 tar -cf - / | gzip > 本机`，**两次都在 ~110MB 处断掉，
设备随后 30 秒完全不响应 ping**。分离测试后确认不是带宽问题（纯流量压测
400MB/20s 跑完，约 20MB/s）—— 是设备端 `tar` 边读边往外吐时 USB NCM 链路会 stall。

所以改成两段：

1. 设备本地 `tar` 落盘（不压缩：设备 CPU 慢，拉回时再压也不迟）；
   传输阶段只剩一个顺序大文件拷贝，绕开了这个问题。USB 接在繁忙 hub 上时尤其要这样走。
2. 拉回走 **HTTP**（设备起 `python3 -m http.server`，只绑 `172.16.42.1`），
   用 `curl -C -` 支持**断点续传**，中途断了不用从头再来。

> `curl` 那句 `--noproxy '*'` 不能省：开发机上普遍设了 `http_proxy`
> （本机这个指向 `127.0.0.1:3030`），curl 会把 `172.16.42.1` 的请求也发给代理，
> 表现是"TCP 通、curl 却 code=000"。

### 两个必须记住的坑

1. **大批量数据别用 `ssh cat` 直传**（见上）。
2. **`/root` 是 0700**，用 `user` 身份（`odin_ssh`）去读会得到**空结果而不是报错** ——
   差点把一份完好的备份判成"截断"。涉及 `/root` 一律走 `odin_sudo*`。

## 一、前提

1. **手机已解锁 bootloader**（原厂 fastboot 模式下执行过解锁；未解锁要先在原厂系统内
   申请并解锁）。
2. **PC 装好 fastboot**：macOS `brew install android-platform-tools`，
   Debian/Ubuntu `sudo apt install android-tools-fastboot`。
3. **手机电量 > 30%**。
4. **USB 线直连**，不要经过 Type-C Hub —— 接在 hub 上时设备会在 USB 总线上时隐时现，
   诊断会被误导（实测踩过：一度以为刷挂了，其实只是 hub 挡着）。

### 进入 fastboot 的三种方式

| 方式 | 适用 | 说明 |
|---|---|---|
| `flash-all.sh` 的 20 阶段 | 系统还在跑（SSH 可达） | **推荐**，全程无人值守，见下节 |
| 关机后按 **音量减 + 电源键** | 进不了系统 / 20 阶段失败 | 出现 fastboot 屏幕后松手；原厂组合键 |
| `adb reboot bootloader` | 系统里有 adbd | 本项目的 Debian 镜像里**没有 adbd**，仅原厂系统可用 |

验证：`fastboot devices` 应列出设备。

## 二、阶段一览

| 阶段 | 做什么 |
|---|---|
| `00 precheck` | 本机依赖（`fastboot` / `sshpass` / `curl`）、镜像是否齐全、按 `dist/MANIFEST.sha256` 校验 SHA256、判断设备当前状态 |
| `10 backup` | 经 SSH 全量备份真机根文件系统（手机本地打包 + HTTP 拉回，可断点续传） |
| `20 fastboot` | 进入原生 fastboot（**远程完成，见下节**） |
| `30 boot` | `fastboot flash boot lk2nd-odin.img` |
| `40 data` | `fastboot flash userdata odin-debian-sparse.img`（失败自动回退 raw 版） |
| `50 reboot` | `fastboot reboot`，等 PC 上出现 USB NCM 网卡（最多 90s） |
| `60 usbnet` | 等 PC 拿到 `172.16.42.2`（DHCP 优先，超时用静态地址兜底） |
| `70 ssh` | 等 22 端口可达（首启含文件系统扩容，会比较慢，最多 150s） |
| `80 verify` | 跑 9 项验收 |
| `90 handoff` | 收尾提示（登录方式、切完整版的命令） |

等待上限都可以在环境里覆盖：`T_FASTBOOT`（默认 180s）、`T_USBNET`（90s）、
`T_SSH`（150s）、`T_BOOT`（60s）。

镜像路径默认是 `dist/lk2nd-odin.img` 与 `dist/odin-debian-sparse.img`，
可以用 `BOOT_IMG` / `DATA_IMG` / `DATA_IMG_RAW` 覆盖。

如果你是从 GitHub 下载的 CI 产物（而不是本地编的），它们通常不在 `dist/` 根下。
例如放到 `dist/ci/` 时：

```sh
BOOT_IMG=dist/ci/lk2nd-odin.img \
DATA_IMG=dist/ci/odin-debian-sparse.img \
DATA_IMG_RAW=dist/ci/odin-debian.img \
  flash/flash-all.sh --from 20
```

> 别直接把下载来的镜像覆盖 `dist/` 下那两个文件——它们在版本库里是被跟踪的二进制，
> 覆盖会产生巨大的 diff。用环境变量指过去既干净又明确。

从 Release 页面下载的产物建议先按 `SHA256SUMS` 核一遍再刷。注意**不同次构建的镜像
校验和本来就不一样**，要用同一次发布里那份 `SHA256SUMS`。

## 三、★ 20 阶段：怎么远程进 fastboot（整条流程能无人值守的关键）

真机上**没有 adbd**，`/sys/kernel/reboot/mode` 又只收 `cold` / `warm` / `hard`，
拒绝 `bootloader` / `fastboot` / `recovery` ⇒ **从系统内部进不了 fastboot**。

但实测证实：**lk2nd 找不到 `/extlinux/extlinux.conf` 时会自动停在 fastboot**
（`Reverting to android boot` → 失败 → `boot_into_fastboot=true`）。

所以脚本的做法是——**改个名再重启**：

```sh
sudo mv /extlinux/extlinux.conf /extlinux/extlinux.conf.disabled
sync
nohup sh -c "sleep 2; reboot" &
```

重启后 lk2nd 扫不到配置，自动落到 fastboot，PC 上 `fastboot devices` 就能看到设备。
**全程不需要人在机器旁按键。** 刷完之后新系统自带 `/extlinux/extlinux.conf`，
lk2nd 正常引导，无需还原（90 阶段会打印确认）。

若这条不通（比如 lk2nd 本身坏了），脚本会提示人工介入：

```
请人工操作：关机后按住【音量减 + 电源键】进入原厂 fastboot，然后重跑
    flash/flash-all.sh --from 30
```

> `--dry-run` 下不会真的重启，20 阶段会跳过等待（等也等不到），
> 30/40 阶段则假定"已在 fastboot"，好让全流程能预览一遍。

## 四、30 / 40 阶段：刷什么、为什么

### 30 — 刷 lk2nd 到 boot 分区（64M）

```sh
fastboot flash boot dist/lk2nd-odin.img
```

刷的是**精简版**（`lk2nd-odin.img`），不是完整版 `lk2nd.img`。

原因：lk2nd 的 QCDT 表里，`msm8953-smartisan-odin` 的 board-id 是 `<0x0b 0x01>`，
`msm8953-xiaomi-markw` 是 `<0x1000b 0x01>`；而 `VARIANT_MASK=0xff` ⇒ 两者
**variant_id 都是 `0x0b`**，高位 `0x10` 只是 major。未精简的 lk2nd 很可能把票投给 markw。

只有命中 odin 条目，DTB 里的占位 compatible `smartisan,odin-panel` 才会被替换成
真实面板 —— **这是屏幕能否点亮的开关**。精简版去掉了 `msm8953-xiaomi-markw` 与
`sdm450-xiaomi-rosy`，强制命中 odin。

### 40 — 刷 Debian 到 userdata 分区

```sh
fastboot flash userdata dist/odin-debian-sparse.img
```

sparse 版由 fastboot 自动分块传输。**失败会自动回退 raw 版**
（`dist/odin-debian.img`，2 GiB 一次下载，可能超过设备的 max-download-size）。

> **先刷 lk2nd 后刷 userdata 的顺序必须保持**：lk2nd 负责挂载 userdata 去找到
> `/extlinux/extlinux.conf`，顺序反了引导链不成立。
>
> **lk2nd 的 `lib/fs/ext2` 只读 ext2 兼容特性集的文件系统。** 本镜像据此用保守特性集
> 制作（无 extents / 64bit / metadata_csum / huge_file / dir_nlink / extra_isize），
> **切勿用发行版默认 `mkfs.ext4` 重建根分区**，否则 lk2nd 挂载失败、整条引导链不执行。
> 重建配方见 `tools/build-image.sh`。

## 五、50 / 60 / 70 阶段：起来、拿地址、等 SSH

`fastboot reboot` 之后：

- **50** 等 PC 上出现 USB NCM 网卡（macOS 上表现为新的 `enX`），最多 90s。
  没自动拿到地址也不算失败，进 60 用静态兜底。
- **60** 目标是让 PC 持有 **`172.16.42.2`**。设备侧的 dnsmasq 地址池只有这一个地址
  （永远只连一台电脑，任何 MAC 都分到同一个 IP）。
  DHCP 没生效时，脚本会找出那块 USB 网卡并静态配上：

  ```sh
  sudo ifconfig enX inet 172.16.42.2/24 up
  ```

- **70** 等 22 端口可达。首启含 `resize2fs`（2 GiB → userdata 实际容量，实机约 111.9 GiB），
  会比较慢，等满 150s 属正常。

超时仍不可达时，救援通道见 [03-系统使用.md § 四 · USB 救援通道](03-系统使用.md)。

## 六、80 阶段：9 项验收

脚本自动跑，全部通过才继续：

| # | 检查项 | 期望 |
|---|---|---|
| 1 | `hostname` | `odin` |
| 2 | 内核版本 | 含 `6.19` |
| 3 | DSI 连接状态（`/sys/class/drm/card0-DSI-1/status`） | `connected` |
| 4 | `dmesg` 里 `Failed to initialize panel` 计数 | `0` |
| 5 | 背光（`sys/class/backlight/*/brightness`） | `> 0` |
| 6 | `usb0` 地址 | `172.16.42.1` |
| 7 | `wlan0` 存在 | 在 `/sys/class/net/` 里 |
| 8 | 根分区已扩容（`df -h /`） | 容量以 `G` 结尾 |
| 9 | `sshd` | `active` |

有任一项未通过脚本会 `exit 1`，此时用 `--from 80` 可以只重跑验收。

## 七、双 label 引导：默认使用 `l0` 自动切换 USB 角色

`/extlinux/extlinux.conf` 里有两条 label，**内核与 initrd 相同，只有 DTB 不同**：

| label | DTB | 用途 |
|---|---|---|
| `l0`（默认） | `msm8953-smartisan-odin-ft8716.dtb` | 完整版：按 Type-C 方向自动切换 USB 网卡或 OTG host |
| `l0-safe` | `msm8953-smartisan-odin-ft8716-norolesw.dtb` | USB 固定 device（`dr_mode=peripheral`），UDC 恒在，USB 网络 / SSH **不依赖 Type-C 角色判定**；代价：完全没有 OTG host |

镜像是**单一文件系统**（只有 `pmOS_root`，`/boot` 与 `/extlinux` 都在根分区里，
不是 pmOS 那种 `pmOS_boot` + `pmOS_root` 双分区），所以改完重启即可切换：

```sh
ssh user@172.16.42.1
sudo sed -i 's/^default .*/default l0/' /extlinux/extlinux.conf && sudo reboot
```

若完整版起不来，改回 `default l0-safe` 重启即可（前提是你还能 SSH 进去；
起不来就走救援通道）。

### 三个不能违反的约束

1. **两个 label 都用显式 `fdt`，绝不能用 `fdtdir`。**
   lk2nd 的 extlinux 解析里 `fdt` 与 `fdtdir` **互斥**
   （`lk2nd/boot/extlinux.c:394-434`：有 `fdtdir` 时用 `lk2nd,dtb-files` 拼路径并覆盖 `fdt`）。
   而 QCDT 表里同时存在 odin 与 markw，`fdtdir` 会去找镜像里根本不存在的
   `msm8953-xiaomi-markw.dtb` ⇒ 启动失败。
2. **用的是"面板写死 FT8716"的那一对 DTB（`*-ft8716*`），不是自动识别版。**
   写死之后，面板是否点亮与 lk2nd 选中哪个 QCDT 条目无关，排障面小很多。
   自动识别的一对（`msm8953-smartisan-odin.dtb` / `...-norolesw.dtb`）也随镜像发布，
   **换屏后把 `fdt` 改回去即可**。
3. **`append` 行末尾的 `console=tty0` 不能删** —— 它是控制台上屏的开关。
   少了它，屏幕上只有背光没有登录提示，**看起来跟"屏没点亮"一模一样**（实机踩过）。

## 八、状态判定与故障处理

每一步操作前先判状态，在 PC 上依次试，第一个成功的就是当前状态：

```sh
# ① 系统起来了（Debian 运行中）
sshpass -p user ssh -o ConnectTimeout=5 -o StrictHostKeyChecking=no \
    user@172.16.42.1 'hostname; cat /proc/device-tree/model; echo'
#   → "Smartisan U2 Pro (ODIN)" = 我们的 Debian

# ② fastboot
fastboot devices

# ③ 无响应 → 检查是否掉进 9008（EDL）
system_profiler SPUSBDataType 2>/dev/null | grep -iE "9008|QUSB_BULK|qdloader" | head
```

| 现象 | 处置 |
|---|---|
| 20 阶段后 `fastboot devices` 一直空 | 等 3 分钟再试；仍无 → 人工长按电源 10s 关机 → 音量减 + 电源进 fastboot → `--from 30` |
| `fastboot flash` 卡住 / 报 too large | 换 USB 口、换线、不用 hub；改用 raw 版 |
| 刷完重启 SSH 一直不通 | 系统会因启动失败自动回 fastboot → 换镜像或改配置重试 |
| SSH 通但无屏 | 查 `dmesg \| grep -iE "dsi\|panel"`；确认 lk2nd 选中的是不是 odin 条目（见 [04-排障.md § 六](04-排障.md)） |
| lk2nd 菜单上音量键 / 电源键失灵 | 已知问题，见 `reports/003`；不影响本流程 —— PC 上直接 `fastboot` 操作即可绕过菜单 |
| **进 9008（EDL）** | 最坏情况：**按住音量上 + 音量下插线**进 EDL，再用原厂线刷包目录里的 `edl-flash.sh` 全量恢复，需人工 |

### B ↔ C 的环是闭合的

```
C: Debian 运行中 ──① 改名 extlinux.conf + reboot──> B: fastboot
        ^                                                │
        └──────────② flash userdata ③ fastboot reboot─────┘
```

① 的手法与 20 阶段完全相同，所以**刷失败可以反复重试、无需人工**。

## 九、刷完之后

90 阶段会打印：

```
登录：ssh user@172.16.42.1（密码 user）
切完整版（带 OTG）：sudo sed -i 's/^default .*/default l0/' /extlinux/extlinux.conf && sudo reboot
```

拿到 SSH 后建议按这个顺序确认整机：扩容 → WiFi → 基带 → 音频 → 振动 → 按键，
再把 default 改成 `l0` 重启，验证 Type-C 角色切换与 OTG。

系统的日常用法见 [03-系统使用.md](03-系统使用.md)。
