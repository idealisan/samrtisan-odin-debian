# 014 — USB 角色切换（OTG ↔ USB 网络）与救援通道加固待办

日期：2026-08-29　状态：**待办，尚未实施**（本报告只做记录与方案定稿，未改动任何产物）

## 一、问题陈述（一句话）

**内核层支持 USB 角色动态切换，用户态没跟上**：`odin-usb-gadget` 是开机一次性服务，
没有任何东西监听 UDC 的出现与消失，导致 USB 网络（SSH 救援通道）是"开机那一刻定生死"，
且一旦切到 OTG host 就不会再回来。

## 二、为什么现在才提出

首刷信心评估时（见 013 末尾与本次讨论）得到的实测证据：pmOS 的 `markw` 镜像曾成功刷入
Odin，网络与 USB SSH 可用、仅部分驱动有问题。该镜像用的是**通用 msm8953 DTB**——
里面**没有 Type-C 角色切换**。而我们的 odin DTB 引入了 `usb-role-switch` + FUSB301，
于是多出一个 markw 那次没有验证过的依赖：**UDC 是否存在，取决于开机时 CC 引脚的判定结果**。

风险因此收敛成单点：不是"主线能不能跑"（已由 markw 实测背书），而是"UDC 在开机那一刻在不在"。

## 三、证据

### 3.1 内核层：能动态切（设计如此）

- `evidence/msm8953-smartisan-odin.kernel.dts:1837-1853`：
  `maximum-speed = "high-speed"`、`usb-role-switch`、`dr_mode = "otg"`、
  `ports/port@0/endpoint` → `remote-endpoint` 指向 `usb-c-connector`
- 连接器节点挂在 fusb301 下（`compatible = "usb-c-connector"`，`power-role = "dual"`）
- `patches/0002`（FUSB301 驱动）：
  - `fusb301_probe():446-454` "Report initial state" —— 若 `FUSB301_ATTACH` 置位则立即
    `fusb301_attach()`，即**插着线开机时能拿到 UDC**
  - attach 路径调用 `usb_role_switch_set_role()` 切角色
  - `chip->cap.prefer_role = TYPEC_NO_PREFERRED_ROLE`（由 CC 判定决定，不强制）
- 内核配置：`CONFIG_TYPEC_FUSB301=y`（**内建，无 udev 加载竞态**）、`CONFIG_USB_DWC3=y`、
  `CONFIG_USB_DWC3_DUAL_ROLE=y`、`CONFIG_USB_ROLE_SWITCH=y`、`CONFIG_USB_CONFIGFS_NCM=y`

### 3.2 用户态：一次性，无监听

镜像实测（debugfs，真机镜像）：

- `/etc/udev/rules.d/` **空目录**，一条规则都没有
- `/etc/systemd/system/odin-usb-gadget.service`：`Type=forking` + `RemainAfterExit=yes`
  的一次性单元，`After=systemd-modules-load.service`，跑完即退出
- `/usr/local/sbin/odin-usb-gadget.sh`（`set -e`）：
  ```sh
  UDC=$(ls /sys/class/udc | head -n1)
  [ -n "$UDC" ] && echo "$UDC" > $CFG/UDC   # UDC 为空 → set -e 直接退出
  ip link set usb0 up                        # → 失败 → 服务永久 failed
  ```
- `/usr/bin/udisksctl` 不存在 → **OTG 接 U 盘没有自动挂载**，需手工 mount

## 四、影响场景

| # | 场景 | 结果 |
|---|---|---|
| 1 | 开机时插着 PC（正常刷机流程） | 角色=device → UDC 在 → usb0+dnsmasq 配好 → **SSH 可用** ✅ |
| 2 | 开机时未插线 / CC 判成 host 或 none | 那一刻 UDC 不在 → 脚本失败 → **之后再插线也不会重配 usb0** ❌ |
| 3 | 开机正常，中途插 OTG U 盘再插回 PC | 切 host → UDC 解绑、usb0/dnsmasq 消失；切回 device → UDC 回来了，
      但**没人重新 bind gadget、重新加地址** → USB 网络死到重启 ❌ |
| 4 | OTG 接 U 盘 | 识别为 sdX，但无自动挂载，需手工 `mount` ⚠️ |

注：configfs 里的 gadget 目录本身会保留，但 **UDC 重新出现后必须重新写一次 `$CFG/UDC`
才会重新绑定**，内核不会自动恢复。

## 五、处置方案（两阶段）

### 阶段 A —— 首刷前，把 SSH 这条命根子钉死

| 编号 | 动作 | 说明 |
|---|---|---|
| A1 | 重写 `odin-usb-gadget.sh` | 轮询等待 UDC（最多 60s，每秒一次）；幂等可重入（已存在配置则跳过重建）；UDC 始终等不到则记日志退出 0（不留 failed 单元） |
| A2 | 新增 `/etc/udev/rules.d/99-odin-udc.rules` | `SUBSYSTEM=="udc", ACTION=="add"` → 重跑 gadget 配置；`ACTION=="remove"` → 停 dnsmasq 清理 |
| A3 | 新增"USB 安全版" DTB | 去掉 `usb-role-switch`、`dr_mode = "peripheral"`，编译为
      `msm8953-smartisan-odin-norolesw.dtb` 放进 `/boot/dtbs/qcom/` |
| A4 | `extlinux.conf` 增加第二个 label | lk2nd 的 token_map 支持 `devicetree` 指令；**首刷把安全版设为 `default`** |

A3/A4 的取舍：安全版 = **USB 网络永远在、彻底失去 OTG host**。首刷用它把行为对齐 markw
那次已验证的配置；拿到 SSH 后再切回完整 DTB。

### 阶段 B —— SSH 打通之后，再做真动态

| 编号 | 动作 |
|---|---|
| B1 | 把 `default` 切回完整 DTB（Type-C + OTG 全功能） |
| B2 | 装 udisks2，实现 OTG U 盘自动挂载 |
| B3 | 真机验证三种场景：插 PC → 出 usb0；插 U 盘 → 出 sdX 且自动挂载；来回插拔 → 每次都能恢复 |

## 六、真机验证清单（阶段 B 用）

```sh
ls /sys/class/udc                       # 有输出 = gadget 就绪
cat /sys/class/typec/port0/data_role    # device / host
nmcli device status                     # usb0 必须是 unmanaged（013 的 P0-2 修复）
systemctl status odin-usb-gadget        # 不得为 failed
ip -4 addr show usb0                    # 172.16.42.1/24
```

## 七、为什么不在首刷前直接做完整动态切换

动态切换无法在本环境验证——QEMU 没有 UDC、也没有 Type-C 控制器。而调试它需要你已经能
登录。**用无法验证的东西去换唯一登录通道的确定性，顺序反了。**

## 八、首刷当天的操作提醒（已同步到 dist/FLASH.md）

- **首次启动务必保持 USB 线连着电脑**，让开机那一刻 CC 判定为 device。
- 若开机后 PC 没出现网卡：先别慌着重刷，等 60s（A1 的等待窗口），再看串口
  `ls /sys/class/udc` 与 `systemctl status odin-usb-gadget`。
