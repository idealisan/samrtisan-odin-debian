# 022 本机自带模块可用性调研

调研对象：**Smartisan U2 Pro（ODIN）**，SoC = **骁龙 626（MSM8953 Pro）**，主线 Linux 6.19 + Debian 12。

调研方式：以**原厂 DTS**（`evidence/stock.dts`，从原厂 DTB 反编译，11928 行）——说明"这台机器板子上焊了什么"；以**本机跑 pmOS 时的第一手采集**（`evidence/device-probe/`、`reports/016`）——说明"什么真跑起来过"；以 **markw 的 DTB**（`evidence/live-device-backup/pmos-diag/boot/msm8953-xiaomi-markw.dtb`，同 SoC 实配）——提供接线参考；主线同 SoC 机型 DTS 提供先例。

> ⚠️ postmarketOS 的 wiki 对这台机器没有专门页面，只有按 SoC 归类的
> `Snapdragon 450/625/626/632 (MSM8953)` 大页，**只能当参考，不能当依据**。
>
> ⚠️ 更要紧的一条：**"pmOS 上能用"推不出"主线能用"**。pmOS 的内核是
> `msm8953-mainline/linux` **fork**，不是主线。有 6 个模块卡在这上面。

## 二、最有价值的三条结论

### 1. 触摸屏不是"主线不支持"

`reports/016` §2.5 写"内核无 FTS 驱动，需另外移植"——**那是 pmOS 6.17 的情况，对主线 6.19 不成立**。

- 主线 `drivers/input/touchscreen/edt-ft5x06.c:1516-1529` 的 compatible 表里有
  `focaltech,ft8716`、`focaltech,ft8719`（以及 ft5426/ft5452/ft6236/ft8201 等整个 FocalTech 家族）
- `CONFIG_TOUCHSCREEN_EDT_FT5X06=m` **已开**

**主线同 SoC 的 `msm8953-xiaomi-daisy.dts:134-152`（Mi A2 Lite）与我们原厂 DTS 逐项对照：**

| 项 | daisy（主线先例） | ODIN 原厂（`stock.dts:6367`） | 一致 |
|---|---|---|---|
| 总线 | `&i2c_3` = 78b7000 | `i22c@78b7000` | ✅ |
| I2C 地址 | `0x38` | `0x38` | ✅ |
| reset GPIO | `tlmm 64` | `focaltech,reset-gpio = GPIO 64` | ✅ |
| irq GPIO | `tlmm 65` | `focaltech,irq-gpio = GPIO 65` | ✅ |
| 供电 | `pm8953_l10` | `vcc_i2c-supply`（未展开查是哪个 LDO） | 待定 |
| 横分辨率 | 1080 | 1080 | ✅ |
| 纵分辨率 | 2280 | **1920** | ❌（我们是 1080×1920，framebuffer 已证实） |

这是一份"几乎可以直接抄"的先例。建议接线：

```dts
&i2c_3 {
	status = "okay";

	touchscreen@38 {
		compatible = "focaltech,ft8716", "focaltech,ft8719", "edt,edt-ft5406";
		reg = <0x38>;
		interrupt-parent = <&tlmm>;
		interrupts = <65 IRQ_TYPE_EDGE_FALLING>;
		reset-gpios = <&tlmm 64 GPIO_ACTIVE_LOW>;
		vcc-supply = <&pm8953_l10>;
		touchscreen-size-x = <1080>;
		touchscreen-size-y = <1920>;
	};
};
```

写多个 compatible 让内核依次匹配**是 DT 的标准做法，不是 hack**。

注意两点：
- 原厂 DTS 里还有 `novatek@01`（`novatek,NVT-ts`）共用同一对 GPIO，是"二选一"的料单。
  本机面板是 NT36672 还是 FT8716 取决于两颗 GPIO（`reports/009`：
  `g91&&g92 → NT36672`、`g91&&!g92 → FT8716`、否则 `SHARP_FT8716` 兜底），**逐台不同**。
  若走 Novatek 则需 `novatek,nt36672a-ts` 并开 `CONFIG_TOUCHSCREEN_NOVATEK_NVT_TS`。
- 还需在 `&tlmm` 里补 GPIO 64/65 的 pinctrl（当前只有 gpio85/gpio61/gpio24/gpio38）。

### 2. `&lpass`（ADSP）是上游默认 disabled——音频整条链路断掉的根因

```
msm8953.dtsi:2092  lpass: remoteproc@c200000   compatible = "qcom,msm8953-adsp-pil"   status = "disabled"
msm8953.dtsi:1421  mpss:  remoteproc@4080000   compatible = "qcom,msm8953-mss-pil"    status = "disabled"
```

这跟 WiFi 的 `wcnss` 是完全一样的剧本：**上游 SoC 级默认值，机型 DTS 自己 opt-in**。
我们 DTS 只启用了 `&wcnss`，`&lpass` 和 `&mpss` 都没动 ⟹ 真机只有 `remoteproc0`（wcnss）一个。

实测佐证：`lsmod | grep snd` 为空，`/proc/asound/cards` = no soundcards。
而编解码/通路模块**全都是 =m 且都已编出**（`SND_SOC_MSM8916_WCD_ANALOG/DIGITAL`、
`SND_SOC_APQ8016_SBC`、`SND_SOC_QDSP6_AFE/ASM/ADM/ROUTING`），只是没加载。

**启用步骤（按顺序）：**
1. `&lpass { status = "okay"; };` —— 主线驱动在 `drivers/remoteproc/qcom_q6v5_pas.c:1444`
2. ADSP 固件 `adsp.mdt` 从 **dsp 分区**（`/dev/disk/by-partlabel/dsp`，原厂 16 MiB ext4）取，
   照抄 `dist/build/rootfs/usr/local/sbin/odin-wlan-fw.sh` 的"开机从原厂分区现取"模式
3. 加 sound 节点（见下）

**声卡机器驱动这一层有个真问题，未决：**

- markw 的 DTB 里声卡 compatible 是 **`qcom,msm8953-qdsp6-sndcard`**
- 主线 6.19 的 `sound/soc/qcom/apq8016_sbc.c:329-333` **只认两个**：
  `qcom,apq8016-sbc-sndcard` 和 `qcom,msm8916-qdsp6-sndcard`。全树 grep 确认没有 msm8953 变体
- 所以 pmOS 那个"音频能用"来自 fork 补丁

两条路：
- (a) **先用主线现成的 `qcom,msm8916-qdsp6-sndcard` 试**：它要求必带 `mic-iomux` + `spkr-iomux`
  两个 reg（`apq8016_sbc.c:315-321`，缺了 probe 直接失败）。`mic-iomux` 在 0xc051000、
  `spkr-iomux` 在 0xc051004（从 markw DTB 拿到，与主线 msm8916 的 LPASS 布局同域）
- (b) 从 msm8953-mainline 合入 `qcom,msm8953-qdsp6-sndcard` 补丁

倾向先 (a)：(a) 是 (b) 的子集，先验证通路通不通，成本最低。

声卡节点本体（照 markw DTB 抄）：
- `codec@c0f0000` → `qcom,msm8916-wcd-digital-codec`，`reg = <0xc0f0000 0x400>`
  （**这个地址原厂 DTS 里也写死了：`qcom,dig-cdc-base-addr = <0xc0f0000>`，两个来源互相印证**）
- `&spmi_bus { pmic@1 { audio-codec@f000 { compatible = "qcom,pm8916-wcd-analog-codec"; reg = <0xf000 0x200>; } } }`
  —— 注意 `pm8953.dtsi:122` 的 `pmic@1` 是空的，codec 子节点要自己在 board DTS 补
- `sound-card@c051000` → 上述 compatible，带 mm1~mm4 / primary-mi2s / tertiary-mi2s 等 dai-link

**用户态**：`alsa-ucm2` 配置完全没有（`/usr/share/alsa/ucm2/` 不存在），也没有 `alsa-utils`，
pipewire/wireplumber 没在跑。pmOS 用的是 `soc-qcom-msm8953-ucm`，源码在
`github.com/msm8953-mainline/alsa-ucm-conf`。这块要单独搬。

### 3. "pmOS 上能用"推不出"主线能用"

pmOS 的 `linux-postmarketos-qcom-msm8953` 用的是 `msm8953-mainline/linux` fork，不是主线。
**受影响的模块**：声卡机器驱动、充电、电量计、振动马达、地磁/距离感（SSC）、S5K3L8 摄像头、扬声器功放接法。

## 三、"需接线"各项的具体接法（按可操作性排序）

1. **触摸屏**（`&i2c_3` + 节点 + pinctrl）—— 主线驱动现成、CONFIG 现成，接线量小，收益最大。
2. **加速度计 + 陀螺仪**（i2c-gpio 节点）—— CONFIG 全开，只差一个节点，且有本机实测先例。**最稳的一项。**
   ```dts
   i2c-gpio {
   	compatible = "i2c-gpio";
   	sda-gpios = <&tlmm 14 (GPIO_ACTIVE_HIGH|GPIO_OPEN_DRAIN)>;
   	scl-gpios = <&tlmm 15 (GPIO_ACTIVE_HIGH|GPIO_OPEN_DRAIN)>;
   	i2c-gpio,delay-us = <2>;
   	#address-cells = <1>; #size-cells = <0>;
   	imu@68 {
   		compatible = "bosch,bmi120";
   		reg = <0x68>;
   		vdd-supply = <...>;      // 需换成我们自己的 LDO
   		vddio-supply = <...>;
   		mount-matrix = "0", "-1", "0", "-1", "0", "0", "0", "0", "1";
   	};
   };
   ```
   注意三点：
   - `sda-gpios` 写的是 tlmm 14/15；pmOS 日志里的 526/527 是同一对引脚加了 512 的偏移
   - `mount-matrix` 是 markw 的摆放方向，**我们不一定一样**，照抄可能导致屏幕旋转判断反了
   - `vdd`/`vddio` 的 phandle 必须换成 `msm8953-smartisan-odin.dts` 里的 LDO
     （建议 l6 1.8V / l9 3.0-3.3V，但要参考原厂 DTS 的 `cam_vio` 之类同域电源再定）
   - markw 的 `light@23`（ltr559）和 `magnetometer@2e`（yas537）**不要抄**——那是红米的料

3. **蓝牙**（装 bluez + 可选 `local-bd-address`）—— 内核侧完全就绪（hci0 已注册）。
   - 真机现状：`dpkg -l` 只有 `libbluetooth3`，**没有 bluetoothd、没有 bluetoothctl、没有 bluez**
   - `&wcnss_bt { local-bd-address = [xx xx xx xx xx xx]; };`（`msm8953.dtsi:2002` 已定义 `wcnss_bt` 标签）
     这是 HCI 子系统的**正式 DT 属性**，不是 work around：
     `btqcomsmd_setup()`（`drivers/bluetooth/btqcomsmd.c:108`）会打上 `HCI_QUIRK_USE_BDADDR_PROPERTY`，
     `hci_sync.c:3593 hci_dev_get_bd_addr_from_property()` 读 fwnode 的 `local-bd-address`；
     读不到就把 hdev 标记成 `HCI_UNCONFIGURED`，`bluetoothctl` 会显示控制器未配置。
     不加也能用（用户态 `btmgmt public-addr` 设一个）。
   - **不需要固件**：pmOS 在这台机器上有 `qca/nvm_00150100.bin` + `qca/rampatch_00150100.bin`，
     但那些是 `hci_qca`（UART 挂 QCA）走 `qca_uart_setup()` 用的；
     SMD 路径的 `btqcomsmd` 从不调它。**不要为蓝牙去扒原厂分区找固件。**

4. **音频**（`&lpass` + sound 节点 + adsp 固件 + UCM）—— 见 §二.2，卡在机器驱动 compatible 上。

5. **相机闪光灯**（开 `CONFIG_LEDS_QCOM_FLASH` + pmic@3 加 `qcom,spmi-flash-led` 节点）—— 单行改动，顺手做。
   主线 DTS 先例 `hamoa-pmics.dtsi:307` 用的是 `"qcom,pm8550-flash-led", "qcom,spmi-flash-led"`；
   下游 `qcom,qpnp-flash-led` → 主线 `qcom,spmi-flash-led` 的映射**未实测**。

6. **摄像头**（camss + cci + 传感器节点，开 `CONFIG_VIDEO_IMX258`）—— 工作量大，且传感器型号未定。
   - 照 markw DTB 抄 `camss@1b00020` + `cci@1b0c000`（`markw.dts:2080` 附近、`:2110`）
   - 注意 `i2c-qcom-cci` 在主线的 compatible 是 `qcom,msm8974-cci`（markw 用的这个）
   - **主线 `msm8953.dtsi` 里根本没有 camss 节点**，也不在任何一个 msm8953 机型 DTS 里（vince/daisy/
     potter/mido/tissot/rimob/FP3 一个都没有）—— 这一项是要自己写，不是抄现成的

7. **电量计 / 充电**（移植 fork 补丁）—— 优先级取决于要不要低电量保护。

8. **振动马达**（移植 fork 补丁）—— 优先级最低。

### 充电 / 电量计 / 振动的精确接线参数（从 markw DTB 挖到）

这三项 DTS 怎么接**已经完全确定**，纯粹只缺驱动：

```dts
&spmi_bus {
	pmic@2 {
		smbchager@1000 {                       /* 充电 */
			compatible = "qcom,pmi8996-smbchg";
			reg = <0x1000>;
			smbchg-lite;
			monitored-battery = <&battery>;
			/* 31 个中断，<0x02 0x1X 0x0Y 0x03> 形式 */
		};
		fuel-gauge@4000 {                      /* 电量计 */
			compatible = "qcom,pmi8996-fg";
			reg = <0x4000>;
			interrupts = <0x02 0x40 0x04 0x01 0x02 0x44 0x00 0x03>;
			interrupt-names = "soc-delta", "mem-avail";
			monitored-battery = <&battery>;
			power-supplies = <&smbchager>;
		};
	};
	pmic@3 {
		haptics@c000 {                         /* 振动马达 */
			compatible = "qcom,pmi8950-haptics", "qcom,spmi-haptics";
			reg = <0xc000>;
			interrupts = <0x03 0xc0 0x00 0x03 0x03 0xc0 0x01 0x03>;
			interrupt-names = "short", "play";
			qcom,play-mode = <0>;      /* buffer */
			qcom,actuator-type = <1>;  /* LRA */
			qcom,wave-shape = <1>;     /* sine */
			qcom,wave-play-rate-us = <5263>;
			qcom,brake-pattern = <3 3 0 0>;
		};
	};
};

battery {
	compatible = "simple-battery";
	charge-full-design-microamp-hours = <3500000>;
	voltage-min-design-microvolt = <3400000>;
	voltage-max-design-microvolt = <4402000>;
	constant-charge-current-max-microamp = <1000000>;
};
```

出处：`markw.dts:2649-2666`（充电）、`:2668-2676`（电量计）、`:2716-2727`（振动）、`:3998-4005`（battery）。

**两处更正 `reports/016`：**
- compatible 是 **`qcom,pmi8996-fg`**，不是 016 写的 `qcom-pmi8994-fg`（pmi8994 是驱动/模块名，pmi8996 才是 DT compatible）。写 DTS 必须用 `qcom,pmi8996-fg`，写 pmi8994 匹配不上。
- smbcharger 的 SPMI 地址 **0x1000**（016 没给；原厂 DTS 里 `qcom,qpnp-smbcharger` 是 `spmi-dev-container` 没写 reg，所以只能从 markw 实配拿）。

振动参数与原厂 DTS **互相印证**：`stock.dts:8913` 的 `qcom,haptic@c000` 也在 pmic@3 的 0xc000，
也是 `actuator-type = "lra"`、`wave-shape = "sine"`、`play-mode = "buffer"`。**这项可以放心抄。**

电池参数来源 `stock.dts:11889`（`qcom,battery-data`）：
- `smartisan_atl_3500mAh` / `smartisan_scud_3500mAh`（两家供应商，`qcom,batt-id-kohm` 10 / 100 区分）
- `qcom,max-voltage-uv = 0x432380` = **4 402 048 µV**（016 实测读到 4.405 V，互相印证）
- `qcom,nom-batt-capacity-mah = 0xdac` = 3500 mAh
- `qcom,fastchg-current-ma = 3500`（在 smbcharger 节点 `stock.dts:8561`）—— 注意这是下游私有属性，
  主线 `simple-battery` 的 `constant-charge-current-max-microamp` 语义不同，**别直接把 3500 填进去**

**未决**：`voltage-min-design-microvolt` 原厂 DTS 没有（下游不写），3.4 V 是从 markw 借的通用 Li-ion 值（推测）。
`constant-charge-current-max-microamp` 填 1A 还是 3.5A，取决于回合过来的充电驱动怎么定义这个字段（推测）。

## 四、摄像头传感器：只能给候选集，不能给确定值

原厂 DTS 里**没有**传感器型号（下游把型号放在用户态 sensor lib）。从原厂 ROM 的
`/etc/camera/camera_config.xml`（从 `system_4.img` 偏移 22392034 处抠出）读到的是**厂商 BOM 选项表**，
不是本机实配：

```
CameraId 2 (FRONT)     : ov8856 | ov8856_qtech | s5k3p3st | s5k3p3st_qtech
                         eeprom = s5k3p3st_ov8856_gt24c64a
CameraId 0 (BACK)      : ov13855_sunny | imx258 | s5k3l8
                         eeprom = imx258_s5k3l8_gt24c64a
CameraId 1 (BACK_AUX)  : ov13855_mono_sunny | imx258_mono | s5k3l8_mono
                         eeprom = imx258_s5k3l8_mono_gt24c64a
```

下游相机栈开机时按顺序试每一组，靠读 EEPROM 判断实际焊了哪颗。所以：
- **后摄 ∈ {IMX258, S5K3L8, OV13855-Sunny}**
- **副后摄 ∈ {IMX258_mono, S5K3L8_mono, OV13855_mono_sunny}**
- **前摄 ∈ {OV8856, S5K3P3ST}**

主线驱动情况：
- IMX258 **有**（`imx258.c`），`CONFIG_VIDEO_IMX258` 未开
- OV8856 **有**（`ov8856.c`），`CONFIG_VIDEO_OV8856` 未开
- S5K3L8、S5K3P3ST、OV13855 **主线无**（`ov13858.c` 不是 13855）

原厂 DTS 有 **3 个相机槽位且全部 `status="ok"`**（`qcom,camera@0` rear 带闪光灯+对焦马达、
`qcom,camera@1` rear 无闪光灯、`qcom,camera@2` front），与"两个摄像头"的说法不冲突（不同 SKU 或指代不同）。

**怎么一锤定音**（都需要先接好 CAMSS/CCI）：
1. 读 EEPROM：CCI 总线上挂的 GT24C64A（I2C 0xA0，原厂 DTS `qcom,eeprom@*` 的 `qcom,slave-addr = <0xa0>`）
   里存着模组型号字符串，`i2cdump` 读出来即可
2. 把三个 compatible 全写上，看哪个 probe 成功

**实操顺序不变**：先接 camss+cci，型号自然就知道了。不建议为定型号单独投入。

## 五、明确建议砍掉的项

| 项 | 理由 |
|---|---|
| 指纹 | 主线既无驱动，也无"指纹"这个设备类别的内核框架（Linux 没有 fingerprint 子系统）。原厂那套 `goodixfp.mdt/.b00~.b06` 是 PIL/TZ 固件，需 qseecom + SCM 调用，主线没有对应加载路径。要做得：自己写 SPI 驱动 + 通过 TEE 加载固件 + 写用户态守护。**最重的一块，且对"当小服务器用"这个目标毫无帮助**。 |
| FM 收音 | 主线无 iris radio 驱动，纯 Android 功能 |
| 光感（TCS3400） | 主线无驱动；是 ALS+色彩，不做自动亮度也能活 |
| 地磁 / 距离感 | 走 SSC，主线无 SSC 框架（不只是缺驱动，是缺整个 sensor hub 子系统）。除非哪天主线合了 SSC |
| 通知灯 | 主线无 `leds-qpnp`；对服务器用途无价值 |
| NFC | 线圈已损坏 |

**值得考虑回合 fork 补丁的**（这 4 个都是 SPMI platform 驱动，不依赖 ADSP/modem/SSC，相对干净）：
`qcom,pmi8996-smbchg`（充电）、`qcom,pmi8996-fg`（电量计）、`qcom,pmi8950-haptics`/`qcom,spmi-haptics`（振动）、
声卡机器驱动。

**旁证**：我们自己已经有 `usb_otg_vbus: otg-vbus { compatible = "qcom,pmi8950-smbchg-otg"; reg = <0x1200 0x100>; }`
（`msm8953-smartisan-odin.dts` 里），对应 `drivers/regulator/qcom-smbchg-otg.c` 是**我们自己加的**补丁
（`1d12b99be`）。说明同一块 PMI8950 的充电寄存器组我们已经能访问 ⟹ 距离完整充电支持只差 charger + fg 两个驱动。

## 六、电池不可观测的后果

现在**完全看不到电池状态**（无 charger 驱动 ⟹ 无 power_supply 设备 ⟹ `/sys/class/power_supply/` 为空）：

- 不知道剩余电量，掉电会直接关机（无低电量告警/自动关机保护）
- 不知道有没有插着电
- 读不到充电电流

**但不会因为没驱动就充不了电**——PMI8950 的充电是硬件自主管理，插上 USB 就会充，不需要内核参与。
所以"当热点用"在功能上不受影响，只是**不可观测、没有低电量保护**。短期可接受，长期跑建议至少把 fg（电量计）搞定。

## 八、方法论备忘（这次调研的两条教训）

1. **依据优先级**：原厂 DTS（本机实配）> 本机跑 pmOS 时的第一手采集 > markw DTB（同 SoC 实配）>
   主线同 SoC 机型 DTS > pmOS wiki / 网上资料（仅参考）

2. **不要把"我们没接好线"误判成"硬件没有"**。这个项目已经错过三次：
   「设备没有 WiFi 硬件」（实际有，只是 DTS 里 `wcnss` 是上游默认 disabled）、
   「设备没有 RTC」（实际有 PMIC 内置 RTC）、
   「设备没有蜂窝基带」（实际基带跑得好好的）。
   **每次都是"硬件在、配置或数据不对"。** 看到某功能不工作，先查 DTS 节点的 `status`、
   内核 CONFIG、固件在不在，别急着下"不支持"的结论。

3. **不要提议奇怪的 work around**，优先找标准机制为什么没生效。
