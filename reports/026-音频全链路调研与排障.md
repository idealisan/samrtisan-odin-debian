## 1. 硬件与软件栈

- SoC：msm8953 / SDM450；内核 Linux 6.19（pmOS `6.19.5/main`）
- machine driver：**`qcom-apq8016-sbc`**（`sound/soc/qcom/apq8016_sbc.c`）。
  设备树 compatible 是 `qcom,msm8953-qdsp6-sndcard`，走 `msm8953_qdsp6_add_ops`
- codec 两块：
  - `audio-codec@f000`（PM8953 下）→ `qcom,pm8916-wcd-analog-codec`（模拟侧：SPK / EAR / HPH / LINEOUT / MIC）
  - `codec@c0f0000` → `qcom,msm8916-wcd-digital-codec`（数字侧：RX1/2/3 MIX、PDM、I2S）
- 外部功放：**型号未知**（见 §6）

信号链：

```
播放：aplay → FE "MultiMedia1"(q6asm) → AFE PRI_MI2S_RX
      → DIGITAL: AIF1 Playback → I2S RX1 → RX3 MIX1(INP1=RX1) → PDM_RX3
      → ANALOG: PDM_RX3 → SPK DAC → SPK PA → SPKR_CLK → SPK_OUT → 外部功放 → 扬声器

采集：麦克风 → AMIC2/INP3 → ADC2 → DEC1 → CIC1 → TERT_MI2S_TX → MultiMedia2(q6asm) → arecord
```

### 1.1 让声卡出现需要启用的三个节点

`&lpass`（ADSP remoteproc `@c200000`）、`&sound_card`（`@c051000`）、`audio-codec@f000` —— 三者原本都是 `disabled`。

ADSP 固件 `adsp.mdt` + `adsp.b00~b13` 来自 **modem 分区** `/dev/disk/by-partlabel/modem` 的 `/image/` 目录。
**注意：dsp 分区里没有这些固件**，它装的是 Android 用户态 DSP 库（AlacDecoderModule.so、DTS_HPX_MODULE.so、DolbyMobileModule.so、fastrpc_shell_0、libFastRPC_UTF_Forward_skel.so 等）。

## 5. 方法论教训（本轮踩过的坑，务必记住）

### 5.1 ⚠️ `/tmp` 是 tmpfs，重启即清空

多次重启后直接跑 `aplay /tmp/song.wav`，文件早已不存在，`aplay` 报 `No such file or directory` 后立刻退出。
**那些"播放"全是空放**，据此得出的一批数据是废的。
echo "已追加 5.1 开头"; tail -3 reports/026-音频全链路调研与排
**修正后的做法**：每次重启后第一件事是重新上传测试音频，并用 `ls -l` 确认大小，再相信播放结果。

判断"播放到底有没有真的跑"的三个信号：
1. aplay 是否立刻返回（无 `Playing WAVE` 输出）
2. 文件是否存在
3. `hw_ptr` 是否推进（见 §5.4）

### 5.2 ⚠️ ftrace 在这个内核上不产出数据

追踪 `q6asm_dai_trigger` 等 7 个函数，filter 全部设置成功，但 `entries-written: 0`，差点得出"q6asm 没被调用"的错误结论。

**做了对照实验才救回来**：追踪 ALSA 核心必调的 `snd_pcm_action` / `snd_pcm_do_prepare`，同样为 0 ⇒ 是 ftrace 无效，不是代码没跑。

⇒ **任何"追踪不到调用"的结论，都必须先用必被调用的函数做对照。**

### 5.3 ⚠️ dyndbg 对模块要用 `module <名> +p`，不是 `file <路径> +p`

- `file sound/soc/qcom/qdsp6/* +p` 只匹配到 **7** 条；遍历 `lsmod` 的模块名 `module q6asm +p` 后是 **119** 条（这些驱动都是 `=m`）。

另外：即便开对了也几乎没输出 —— `q6asm-dai.c` 里 dev_dbg 极少。⇒ **"没日志"推不出"代码没执行"。**ODEOF
echo "已续写 5.2-5.3"; date '+[%F %T] 结束'
### 5.4 判断 PCM 是否推进要看 hw_ptr，不能只看 avail/delay

精确采样（每 2 秒一次）：
```
t=1s  hw_ptr:43679    appl_ptr:68639    delay=24960
t=3s  hw_ptr:237119   appl_ptr:262079   delay=24960
t=5s  hw_ptr:430559   appl_ptr:455519   delay=24960
t=7s  hw_ptr:630239   appl_ptr:655199   delay=24960
```
appl_ptr 减 hw_ptr 恒为 buffer_size=24960。hw_ptr 稳定推进（每 2 秒约 +96000 帧 = 48000×2）说明数据在正常流动；`avail=0` 只代表缓冲区被 aplay 喂满，不是停滞。我之前据此误判为"卡住"，已纠正。

### 5.5 该内核没开 sysfs GPIO，也没有 libgpiod 工具

`/sys/class/gpio/export` 不存在，`gpioset` 也没有。运行期改 GPIO 电平只能靠设备树的 gpio-hog（CONFIG_GPIO_SYSFS 未开）。

**重要副作用**：gpio-hog 抢 gpio132 会让整个声卡消失（`no soundcards`）—— 反证 aw8738 驱动确实依赖 `mode-gpios = <&tlmm 132>`。只 hog gpio96（拉低）不破坏声卡。

## 6. 从原厂线刷包挖到的东西

### 6.1 ROM 结构

`/Volumes/caseSensitiveBar/Pro_user_V4.2.5/SEKSA-mol%odin-rom-4.1.0-odin-user-20180523-005028-32g/` 共 103 个文件。除 boot.img / NON-HLOS.bin / 各种 .mbn 外，**还有 system_1.img 到 system_36.img**（system 分区切成 36 块）。

**实用技巧**：这些 system 块是 squashfs 但**数据未压缩**，不需要 simg2img / unsquashfs，直接 `grep -a` 就能搜到 XML 内容。提取某个 path 的完整定义用 Python 找 `<path name="xxx">` 到 `</path>` 之间的字节。

> 教训：第一次列目录用了 head -60，漏看了后面的 system_*.img。列长目录不要截断。

### 6.2 Android 的 speaker 通路定义

在 system_4.img（共 7517 个 ctl）里找到 9 个 speaker 定义，**7 个完全相同，只有两步**：

```xml
<path name="speaker">
    <ctl name="RX3 MIX1 INP1" value="RX1" />
    <ctl name="SPK" value="Switch" />
</path>
```

另外两个版本：

```xml
<!-- offset 59850985：LINE_OUT 版 -->
<path name="speaker">
    <ctl name="RX3 MIX1 INP1" value="RX1" />
    <ctl name="RX3 Digital Volume" value="79" />   <!-- 79 = -5dB，不是 124 -->
    <ctl name="LINE_OUT" value="Switch" />
</path>

<!-- offset 60268837：tasha + WSA 版，本机不用 -->
<path name="speaker">
    <ctl name="SLIM RX1 MUX" value="AIF1_PB" />
    <ctl name="SLIM_0_RX Channels" value="One" />
    <ctl name="RX4 MIX1 INP1" value="RX1" />
    <ctl name="SPK DAC Switch" value="1" />

```

### 6.3 原厂 DTB（evidence/stock-rom-battery/odin-stock.dts）里的功放线索

```
8329:  qcom,ext-pa-enable = <0xbe 0x84 0x00>
         ^ 0x84 = 132 ⇒ gpio132，引脚确认无误

         ^ 0x60 = 96 ⇒ gpio96，sd-n 低有效，正常工作需要拉低

9734: 启用的 sound 节点（msm8952-audio-codec）的 qcom,audio-routing **只定义了 MIC 与 BIAS，没有任何到 speaker 的通路**：
      "RX_BIAS","MCLK" / "SPK_RX_BIAS","MCLK" / "INT_LDO_H","MCLK" /
      "MIC BIAS External","Handset Mic" / "MIC BIAS External2","Headset Mic" /
      "MIC BIAS External","Secondary Mic" /
