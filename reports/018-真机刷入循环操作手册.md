# 018 — 真机刷入循环操作手册（无人值守版）

日期：2026-08-29
适用：**手机旁边没有人**的场景，全部操作通过一根 USB 线远程完成。

---

## 零、先说结论：哪些能远程，哪些不能

| 能力 | 远程可行 | 依据 |
|---|---|---|
| 从系统内重启 | ✅ `systemctl reboot` | — |
| 从系统内触发进 fastboot | ❌ **不可行** | `/sys/kernel/reboot/mode` 只接受 `cold`/`warm`/`hard`，拒绝 `bootloader`/`fastboot`/`recovery`；真机无 `adbd` |
| **靠"引导失败"进 fastboot** | ✅ **可行（本方案核心）** | lk2nd 找不到可启动 fs 后 `Reverting to android boot` → 失败 → `boot_into_fastboot=true`（`app/aboot/aboot.c:5648`、`lk2nd/boot/boot.c:64`） |
| fastboot 下刷 userdata | ✅ | lk2nd fastboot 走 USB `18d1:d00d` |
| fastboot 下重启回系统 | ✅ | `fastboot reboot` |
| **回到 pmOS** | ❌ **不可行** | fastboot 不能改 ext2 内的单个文件；要回 pmOS 只能整体重刷 pmOS 镜像（我没有完整备份） |

⇒ **A（pmOS）→ B（fastboot）是单向门。** 跨过去就回不来了，只能 pmbootstrap 重装。

## 一、状态机

```
   ┌──────────────┐
   │ A: pmOS 运行  │  SSH 172.16.42.1，用户 cheng（doas 提权）
   └──────┬───────┘
          │ ① 改名 extlinux.conf + reboot   【单向，回不来】
          ▼
   ┌──────────────┐
   │ B: Fastboot  │  USB 18d1:d00d，`fastboot` 可操作
   └──────┬───────┘
          │ ② fastboot flash userdata <Debian 镜像>
          │ ③ fastboot reboot
          ▼
   ┌──────────────┐
   │ C: Debian 运行│  SSH 172.16.42.1，用户 user
   └──────┬───────┘
          │ ④ 改名 extlinux.conf + reboot   （与 ① 同手法）
          └────────────► B   ← 这个环是闭合的，可反复刷

   ┌──────────────┐
   │ D: 无响应     │  上述都连不上 → 需人工介入（按键 / 9008 EDL）
   └──────────────┘
```

**关键**：B↔C 的环闭合后，就可以反复刷、反复试，无需人工。
唯一需要一次性承担的风险是 **A→B 那一步**（验证 lk2nd 真的会停在 fastboot）。

## 二、状态判定（每步操作前必做）

在 PC（macOS）上依次执行，第一个成功的就是当前状态：

```sh
# ① 是不是 C / A（系统起来了）
sshpass -p cheng ssh -o ConnectTimeout=5 -o StrictHostKeyChecking=no \
    user@172.16.42.1 'hostname; cat /proc/device-tree/model; echo'
#   → 输出 "Xiaomi Redmi 4 Prime"  = 状态 A（pmOS）
#   → 输出 "Smartisan U2 Pro (ODIN)" = 状态 C（我们的 Debian）✅

# ② 是不是 B（fastboot）
fastboot devices
#   → 列出一行且带 fastboot = 状态 B
#   → 用 system_profiler 复核：
system_profiler SPUSBDataType 2>/dev/null | grep -iE "fastboot|18d1|d00d|qualcomm" | head

# ③ 是不是 D
#   ①②都没有，且过 3 分钟仍无 → 检查是否掉进 9008(EDL)
system_profiler SPUSBDataType 2>/dev/null | grep -iE "9008|QUSB_BULK|qdloader" | head
```

## 三、循环各步的具体命令

### 步骤 ① A/C → B：让引导失败，把 lk2nd 逼进 fastboot

**手法**：把 `/extlinux/extlinux.conf` 改名（**不是删除**，改名后可恢复性最好），
lk2nd 扫描不到可启动配置 → "Reverting to android boot" → 失败 → 停在 fastboot。

```sh
SSHOPT="-o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o ConnectTimeout=5"

# A 状态（pmOS，用户 cheng）
sshpass -p cheng ssh $SSHOPT user@172.16.42.1 \
  'echo cheng | doas -S sh -c "mv /boot/extlinux/extlinux.conf /boot/extlinux/extlinux.conf.disabled; ls -l /boot/extlinux/"'
sshpass -p cheng ssh $SSHOPT user@172.16.42.1 'echo cheng | doas -S systemctl reboot'

# C 状态（我们的 Debian，用户 user；/extlinux 在根分区）
sshpass -p user ssh $SSHOPT user@172.16.42.1 \
  'echo user | sudo -S mv /extlinux/extlinux.conf /extlinux/extlinux.conf.disabled'
sshpass -p user ssh $SSHOPT user@172.16.42.1 'echo user | sudo -S systemctl reboot'

# 等待并判定
sleep 90
fastboot devices          # 期望看到 fastboot 设备
```

> pmOS 的 `/boot` 是独立的 `pmOS_boot` 子分区，extlinux.conf 在 `/boot/extlinux/`；
> 我们的 Debian 是单一文件系统，在 `/extlinux/`。**两个路径别搞混。**

**若 90 秒后 `fastboot devices` 为空**：再等 60 秒重试一次；仍为空则进入 §四 故障处理。

### 步骤 ② B → C：刷入 Debian 系统

```sh
cd odin-port/dist

# 先确认刷的是哪一份（刷前必查 md5）
md5 -q odin-debian.img odin-debian-sparse.img lk2nd.img
#   期望：odin-debian.img        98482fdbdcd15e6f568c162fda3629ca
#        odin-debian-sparse.img  56a2cbca0075c7aac3d184b5f2a618e1
#        lk2nd.img               521d64fcb2ab4cf534bac1f9b8440712

# ⚠️ 只刷 userdata，**不要刷 boot**（保留现有 pmOS 的 lk2nd，它才是救援保障）
fastboot flash userdata odin-debian-sparse.img
# 若报 download too large / 传输中断，改用 raw：
#   fastboot flash userdata odin-debian.img
```

> **绝对不要在这一步刷 `lk2nd.img`**。现有 lk2nd 是我们唯一的救援通道；
> 换成改造版后若它自身启动失败，就没有任何 fastboot 可回（真砖，只能 9008 EDL）。
> 换 lk2nd 是后续单独的一步，风险等级完全不同。

### 步骤 ③ B → C：重启进系统

```sh
fastboot reboot
# 首次启动含在线扩容（2GiB → 111.9GiB），等待 2–4 分钟
sleep 150
sshpass -p user ssh -o ConnectTimeout=10 -o StrictHostKeyChecking=no \
    user@172.16.42.1 'hostname; cat /proc/device-tree/model; df -h /'
```

### 步骤 ④ C 里的验证清单（拿到 SSH 后逐项跑）

```sh
sshpass -p user ssh $SSHOPT user@172.16.42.1 'bash -s' <<'EOS'
echo "--- 引导 ---"
grep -vE "^#|^$" /extlinux/extlinux.conf
echo "--- DTB / 是否命中 odin（决定有没有屏）---"
cat /proc/device-tree/model
tr '\000' ' ' < /sys/firmware/devicetree/base/compatible; echo
echo "panel@0 compatible: $(tr '\000' ' ' < /sys/firmware/devicetree/base/soc@0/display-subsystem@1a00000/dsi@1a94000/panel@0/compatible 2>/dev/null)"
echo "  ↑ 仍是 smartisan,odin-panel = lk2nd 没选中 odin ⇒ 无屏（预期，需后续换 lk2nd）"
echo "  ↑ 变成 odin-r69006/ft8716/nt36672 = 命中有屏 ✅"
echo "--- 扩容 ---"
cat /var/log/odin-resize.log 2>/dev/null | tail -5
df -h /
echo "--- USB / 救援通道 ---"
ls /sys/class/udc; ip -4 -o addr show usb0
nmcli -t -f DEVICE,STATE device status | grep usb0     # 期望 unmanaged
echo "--- 角色脚本 ---"
systemctl is-active odin-usb-gadget odin-usb-gadget.timer
tail -3 /var/log/odin-usb-role.log 2>/dev/null
echo "--- 外置存储（未插盘时应为空，插盘后看 /run/media）---"
ls -l /run/media/ 2>/dev/null || echo "  (未挂载)"
echo "--- failed ---"
systemctl --no-pager --failed | tail -3
EOS
```

### 步骤 ⑤ C → B（再刷一遍）

改回 `extlinux.conf.disabled` 那一套，重复 ①。环是闭合的。

## 四、故障处理

| 现象 | 判定 | 处置 |
|---|---|---|
| ① 后 `fastboot devices` 一直空，SSH 也不通 | 卡在 D | 等 3 分钟再试；仍无 → **需人工**：长按电源 10s 关机 → 音量减+电源进 fastboot |
| `fastboot flash` 卡住 / 报 too large | 传输问题 | 换 USB 口、换线、不用 hub；改用 raw 版 |
| 刷完重启，SSH 一直不通 | 系统没起来 | `fastboot` 应会自动出现（启动失败）→ 回 B → 换镜像或改配置重试 |
| 进 9008（EDL） | 最坏 | 只能原厂线刷包 `edl-flash.sh` 全量恢复，需人工 |
| 系统起来了但无屏 | 预期 | lk2nd 没选中 odin；见 §五 |

## 五、拿到屏的最后一步（风险最高，单独决策）

首刷验证通过、C 状态稳定后，若需要屏幕，才考虑替换 lk2nd：

```sh
# ⚠️ 这一步把唯一的救援通道换成未经实机验证的固件。
#   若改造版 lk2nd 自身启动失败 ⇒ 没有 fastboot ⇒ 真砖 ⇒ 只能 9008 EDL。
fastboot flash boot dist/lk2nd.img
fastboot reboot
```

**替代方案（推荐先试）**：不换 lk2nd，而是**精简 lk2nd 的设备表**——
重新编译一份只保留 `msm8953-smartisan-odin` 一条的 lk2nd，强制命中。
这样即使新固件有问题，它的行为也更简单、更容易停在 fastboot。

| `STATE.txt` | 采集时刻的完整状态快照（lk2nd 版本、extlinux.conf、lsblk、DTB、服务、USB） |

> 它们的作用是"知道原状是什么"，以及在需要时用 pmbootstrap 重装时有参照。
