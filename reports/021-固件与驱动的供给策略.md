# 021 — 固件与驱动的供给策略（后续补驱动的实施规范）

日期：2026-08-30　起因：v0.9.1 真机验收 16 项挂了 1 项（无 `wlan0`）

---

## 零、一句话

**固件必须在驱动第一次索取它之前就位。放到用户态的 late service 里，永远差一步。**

本设备上有相当一部分外设（WiFi / 蜂窝 / 音频 DSP / 各种 remoteproc）的固件
不在任何 Debian 包里，也不能进版本库（二进制；射频校准数据还带机器相关信息）。
它们只能**开机从原厂分区现取**。这篇规定"现取"这件事该放在哪个时间点、怎么做，
以及哪些做法是错的。后面补任何驱动都照此办理。

---

## 一、时序（这是全部问题的根源）

实测开机时间线（`dmesg -T` 时间戳，v0.9.1 真机）：

| 时刻 | 事件 |
|---|---|
| 2.318s | `Run /init` —— 进 initramfs |
| 3.851s | initramfs 把真正的根挂为 ro |
| ~4–6s | `switch_root`，systemd 接管 |
| 6.1–6.2s | systemd 跑完 `basic.target` 之前的各 target |
| 8.969s | 根被 systemd 重挂为 rw |
| **10.230s** | **`qcom_wcnss_pil` 索取 `wcnss.mdt` → 失败 -2** |
| 10.246s | remoteproc 停在 `offline`，此后**不会自己重试** |
| **25.899s** | 旧方案里的 late service 才挂载 persist 分区去取固件 |
| 25.9s+ | 文件到位了，但没人再去要 |

**差了 15 秒。** 而且这不是"多试几次就好了"的问题——remoteproc 的
`request_firmware()` 失败后就把自己留在 `offline`，用户态补上文件不会触发重试。

⇒ 供给动作必须发生在 **switch_root 之前**，也就是 **initramfs 里**。

---

## 二、正确做法

### 2.1 落点：initramfs，不是 systemd service

initramfs 存在的意义就是"在真正的 init 起来之前把根准备就绪"。
固件属于典型的这一类准备工作。

- 源：`dist/build/initramfs/sbin/odin-wlan-fw.sh`
- 挂载点：`dist/build/initramfs/init` 里 `switch_root` **之前**调用
- 目标路径：真实根的挂载点（initramfs 里是 `/mnt`），脚本以参数接收

```
… 找到根并挂到 /mnt …
      ↓
[initramfs] 固件供给（缺文件时才临时 remount,rw）
      ↓
sync → remount,ro
      ↓
mount --move /dev /proc /sys → switch_root
```

### 2.2 不需要 udev 也能按分区名定位

initramfs 里 `/dev/disk/by-partlabel/` 那套符号链接**不存在**（那是 udev 建的）。
但 sysfs 每个块设备的 `uevent` 里就同时有 `DEVNAME` 和 `PARTNAME`：

```sh
$ cat /sys/class/block/mmcblk0p52/uevent
DEVNAME=mmcblk0p52
PARTNAME=modem
```

所以按 GPT 分区名找设备不依赖 udev：

```sh
part_dev() {
	name=$1
	for d in /sys/class/block/*; do
		[ -f "$d/uevent" ] || continue
		if grep -q "^PARTNAME=$name$" "$d/uevent" 2>/dev/null; then
			sed -n 's/^DEVNAME=//p' "$d/uevent" | head -1 | sed 's|^|/dev/|'
			return 0
		fi
	done
	return 1
}
```

> 顺带一个反直觉的事实：**设备上 `/dev/disk/by-partlabel/` 里没有 `lk2nd`，
> 但 `fastboot flash lk2nd` 能用**。因为 `lk2nd` 是 fastboot 层导出的名字
> （`getvar all` 报 `partition-size:lk2nd: 0x80000`），不是 GPT 分区。
> 设备侧看不到、fastboot 侧能刷，两件事并不矛盾。

### 2.3 幂等：只在缺文件时才写

用 `cmp -s` 判定，相同就跳过。不是洁癖——`wcnss.b06` 有 3.2 MB，
没必要每次开机都往闪存重写一遍。

配套的是**只有真的缺文件时才把根临时挂为 rw**：

```sh
if /sbin/odin-wlan-fw.sh /mnt --check; then
    echo "[initramfs] WCNSS 固件已在位"
else
    mount -o remount,rw /mnt
    /sbin/odin-wlan-fw.sh /mnt
    sync
    mount -o remount,ro /mnt     # 立刻挂回去，缩小 rw 窗口
fi
```

绝大多数开机走的是第一条分支，根全程只读。

### 2.4 失败一律不致命

最坏结果只是该外设不可用。**绝不能因为取不到固件把启动搞挂。**
脚本所有可能失败的地方都不影响退出码（末尾 `exit 0`）。

## 三、明确禁止的做法（以及为什么）

| 做法 | 为什么不行 |
|---|---|
| 用 systemd late service 取固件 | 时序上永远晚于驱动的第一次 `request_firmware`（本例晚 15s） |
| 取完再 `modprobe -r X && modprobe X` | **治标。** 而且经常重载错对象——`wcnss.mdt` 是 remoteproc（`qcom_wcnss_pil`）读的，不是 `wcn36xx`；重载 `wcn36xx` 对 remoteproc 毫无影响 |
| 往 sysfs 里 `echo start > remoteproc0/state` 触发重载 | 同上，属于事后补救。它**能**把 WiFi 救回来，但每次开机都要靠一次失败 + 一次补救，不该是设计 |
| 把固件预置进版本库 | 二进制不入库是仓库铁律（README.md:8-14）；射频校准数据还带机器相关信息 |
| 硬编码 `/dev/mmcblk0pNN` | 分区号会随原厂布局变化，且换设备即错。一律按 GPT 分区名 |

> 补充：那两个"补救"动作本身**不是错的**，排障时很有用——
> 想不重启就把 WiFi 拉起来：
> `echo start > /sys/class/remoteproc/remoteproc0/state` 然后
> `modprobe -r wcn36xx; modprobe wcn36xx`。
> 但它们只该出现在 `docs/04-排障.md` 里，不该出现在启动路径上。

## 四、补一个新外设时的实施清单

1. **查清楚是谁在要、什么时候要**
   ```sh
   dmesg -T | grep -iE "firmware|remoteproc|<驱动名>"
   ```
   看时间戳，确认索取发生在 `switch_root` 前后。

2. **确认固件从哪来**
   原厂分区的哪个目录？`mount -o ro` 挂上去看一眼。
   顺手记下文件系统类型——本设备 `modem` 是 **vfat**、`persist` 是 **ext4**，
   两者都是内核内置（`/lib/modules/*/kernel/fs/` 里找不到它们），
   所以 initramfs 里可以直接挂。

3. **判断要不要进 initramfs**
   只要索取发生在用户态之前（基本都会），就进 initramfs。

4. **写脚本**，照 `dist/build/initramfs/sbin/odin-wlan-fw.sh` 的结构：
   - POSIX `sh`（initramfs 是 busybox ash，**没有 bash**）
   - `set -u`，不用 `set -e`（失败要能继续）
   - 目标根以参数接收，支持 `--check`
   - `cmp -s` 幂等
   - 日志走 stderr（initramfs 阶段只有控制台可靠）；真实根有 `/var/log` 时再双写一份

5. **确认 busybox applet 够用**
   名单在 `dist/build/initramfs-applets.txt`，缺什么加什么（每个只是个符号链接）。
   本次补了 `cp` 和 `cmp` —— 原名单里居然没有 `cp`。

6. **先在真机上用假根验证，再发版**
   ```sh
   mkdir -p /tmp/fakeroot
   sudo sh /tmp/odin-wlan-fw.sh /tmp/fakeroot     # 不应碰到真的 /lib/firmware
   sudo sh -c 'cd /tmp/fakeroot/lib/firmware && md5sum * ...'   # 与现网产物比对
   ```
   别拿一次 CI 构建去赌脚本对不对——一个来回是十分钟。

7. **驱动是模块的话，确认加载时机**
   `/etc/modules-load.d/*.conf` 由 `systemd-modules-load` 处理，在 `basic.target`
   之前。固件已在位 ⇒ 第一次加载就成功。
