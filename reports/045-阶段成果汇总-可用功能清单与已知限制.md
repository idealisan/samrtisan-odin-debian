## 二、不能用的 / 还没做的

| 项 | 状态 | 说明 |
|---|---|---|
| **GPS** | ❌ | QRTR 上**没有 16（LOC）服务，也没有 6（PDS）**。modem 通了不等于 GPS 通 —— 这版 modem 固件是否含 GNSS、LOC 是否需要额外触发，都还没查 |
| ModemManager | ❌ | 镜像里被 mask；`mmcli -L` 报 `No modems were found`（需配 QRTR 后端） |
| 地磁 / 罗盘 | ❌ | 三条总线上 `0x0c/0x0d/0x0e/0x1e/0x2e` 全无应答 |
| 指示灯（aw2013） | ❌ | 还没定位在哪个 BLSP 总线上（有 TZ 复位风险，一次只能试一条） |
| 霍尔传感器 | — | 原厂没有 |
| `mount-matrix` | ⚠️ | 仍是照抄 daisy 的占位值，需要把手机平放/立起/侧翻读原始值定符号（要人动手） |
| 显示启动慢 | ⚠️ | 面板要 ~48s 才起来（老记录是 5s）。不影响功能，但要单独查一轮 |
| 键盘"闪一下" | ⚠️ | 控制台整屏刷新时会把键盘顶掉，1 秒后重绘补回。退出登录时可见一次闪烁，已接受 |

## 三、本阶段（v0.9.7 系列）做了什么

### 3.1 触摸屏：从"完全没设备"到可用

**症状**：整机没有触摸设备，dmesg 只有一句 `touchscreen probe failed`。

**根因不是芯片**：FT8716 与显示集成在同一颗 **TDDI** 上，面板没上电它就不应答。
而 `msm`(DRM) 与 `panel_ft8716` 都是模块、靠 udev 冷插加载 —— 实测显示 48s 才起来，
触摸 43s 就 probe，拿 `-5`(EIO) 失败后内核**不再重试**。

**修法**：`odin-touchscreen.service` 绑 `dev-dri-card0.device`，等显示真就绪再强制
重新 probe。**重启验证通过**（开机自动注册）。

> 期间排除了一个诱人但错误的方向：同芯片的 vince 在 DTS 里给触摸写了
> `vcc-supply` + `iovcc-supply`，看着照抄就行。但**原厂 DTB**
> （`odin-stock.dts:6367`）里 `focaltech@38` **只声明了 `vcc_i2c-supply`** ——
> 说明主电与显示共享、没有第二路轨可指。照抄 vince 是猜。

### 3.2 按键映射：照原厂 DTB 改正

只按一下**电源键**却同时冒出两个事件（`KEY_POWER` + `KEY_VOLUMEDOWN`），
导致 thd 匹配不上单键触发器 ⇒ "按了没反应"。这跟 lk2nd 那次的映射错是同一类问题。

原厂铁证（`evidence/stock-rom-battery/odin-stock.dts`）：

- `:11643 gpio_keys` —— 三键全走 TLMM GPIO，low-active，debounce 15
  · GPIO85 → 115 KEY_VOLUMEUP ｜ GPIO86 → 114 KEY_VOLUMEDOWN ｜ GPIO87 → 102 KEY_HOME（`gpio-key,wakeup`）
- `:7932 qcom,pon_2` —— **RESIN 是 `status="disable"`**，原厂根本没拿它当音量−

我们之前两处都错：gpio-keys 只有 volume-up，又把 `&pm8953_resin` enable 成音量−。
现已补齐三键并把 RESIN 禁用；本地编译 4 个 DTB 全过，反编译与原厂逐项一致。

### 3.3 电源键 = 开关屏（不是关机）

`99-odin-powerkey.conf` 早已把 logind 的全部电源动作设成 `ignore`（防兜里误触关机）。
但装了触屏键盘后屏幕常亮，需要关屏办法，于是把电源键借过来：

- **udev 干不了**（只在设备插拔时触发，监听不到按键）→ 用 triggerhappy
- 关**背光** `bl_power`，**不是** console blank —— 后者会被任意输入事件解除，
  实测表现为"灭了马上又亮"
- 关屏顺手停掉键盘，防误触打字、也省掉每秒重绘

### 3.4 第三个变体 kb：core + BuffyBoard 触屏键盘

- 在 arm64 根里借 qemu 编（不交叉编译：动态库链的是根目录自己的 bookworm 库，
  ABI 天然一致，避免 `GLIBC_2.xx not found`）
- 上游钉死：buffybox `3.6.0`，lvgl 子模块 `85aa60d1`；`-Dsystemd=true` 才能生成
  `buffyboard.service` 和给 getty 的 drop-in（新会话时发 `SIGUSR1` 让键盘重绘）
- **每秒全量重绘**：控制台一整屏刷新就把键盘顶黑，用上游 `SIGUSR1` →
  `lv_obj_invalidate(keyboard)` 周期性补回。0.5s 几乎无感但退出时明显闪，1s 仍可
  "闪一下整块亮回来"，取 1s
- 补装 `libinput-bin`（缺 `/usr/share/libinput` 时触摸屏 quirks 不生效）

### 3.5 rmtfs 进 CI

modem 靠 rmtfs 读写 EFS，没有它每约 50s 崩一次。之前只把服务文件进了仓库、
二进制靠手工 scp，重刷就丢。现由 CI 编出并随镜像分发。

为绕开 libudev（交叉编译会撞 glibc 版本错配，且 Debian 不带 `libudev.a`），
上游源码里本来就有读 sysfs 的分支，用 3 行补丁把它变成默认路径，于是可以
**全静态链接** —— 不依赖设备上任何 `.so`，也不受构建机 glibc 版本影响。

### 3.6 modem 供电轨

`mss-supply` 从 RPM 管理的 `s2`（`regulator_set_voltage` 被拒）换成 `s1`
（照抄同芯片的 Asus Zenfone 3），modem 才真正起来。

## 四、这一轮踩到的坑（值得记住）

1. **名单存了三份**：变体名在 Makefile 两处 + `build-rootfs.sh` 一处各有一份。
   加 `kb` 时只改了 Makefile，CI 上 kb job **23 秒**就挂在 `未知变体: kb`。
   这种"多处各存一份"的名单，加值前必须全库搜一遍。
2. **scp 的目标路径别用变量拼**：一次写错的循环把 `thd-libs.tgz` 覆盖到了仓库里
   脚本的路径上，又被 `git add -A` 提交 —— 设备上装到的是压缩包，`sh` 报
   `not found` / `Exec format error`。
3. **`pkill -f "<模式>"` 会匹配到自己那条命令行**，把自己所在的 SSH 会话一起杀掉
   （表现为命令无输出、连接断开）。
4. **hunk 行数用脚本重算，不要手数** —— 手数错过一次，正是那次让 DTB 被截断。

## 五、怎么验收

```sh
# 刷机（全自动，无需人工按键）
bash flash/flash-all.sh

# 机上自检（14 项）
sudo odin-fs-verify.sh
```

手动确认要点：

- 触摸屏：`thd --dump --deviceglob '/dev/input/event*'` 后划屏，应见
  `ABS_MT_POSITION_X/Y` 变化、`BTN_TOUCH=1`
- 震动：`/dev/input/event0` 存在且 `ff` 位支持 `FF_RUMBLE`
- 传感器：八项全部"非 0 且波动"（判据是用户定的）
- 键盘（kb 变体）：屏幕出键盘 → 点键 → 终端有字符；电源键能关屏/开屏
