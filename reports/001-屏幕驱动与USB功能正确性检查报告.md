## 三、发现问题

### 🔴 问题 1【严重】占位 compatible 不匹配 → 面板自动适配完全失效

**位置**
- 内核侧：`linux-msm8953/arch/arm64/boot/dts/qcom/msm8953-smartisan-odin.dts:123`
  ```dts
  compatible = "smartisan,odin-display";
  ```
- lk2nd 侧：`odin-port/lk2nd/0002-msm8953-add-Smartisan-ODIN-device.patch`（及预构建 `lk2nd.img`）
  ```dts
  panel {
      compatible = "smartisan,odin-panel", "lk2nd,panel";
  ```

**根因分析**

`refs/lk2nd/lk2nd/device/panel.c` 的替换逻辑：
```c
/* old = panel 节点 compatible 列表的第一个字符串 */
old = getprop_str(dtb, node, "compatible", &old_len);   // → "smartisan,odin-panel"
...
node = fdt_node_offset_by_compatible(dtb, -1, panel->old_compatible);
```
即 lk2nd 在 Linux DTB 中查找的是 **lk2nd panel 节点的第一个 compatible 字符串 `"smartisan,odin-panel"`**（上游惯例：如 `xiaomi,vince-panel` ↔ 内核侧同名占位符），而非 README 所述的任意约定占位符。

**后果**
1. 启动日志报 `Failed to find panel node with compatible smartisan,odin-panel: -FDT_ERR_NOTFOUND`；
2. `compatible` 不被替换 → 三个面板驱动均无法绑定 → **所有硬件批次黑屏**；
3. 自动适配机制整体失效（fastboot oem panel 切换亦无效）。

**修复方案（二选一）**
- 方案 A（推荐，仅改内核侧）：`odin.dts:123` 改为 `compatible = "smartisan,odin-panel";`，重新编译 DTB；同步修订 `README.md` 第 31 行描述。
- 方案 B（改 bootloader 侧）：patch 0002 及独立 dts 中 panel 节点第一个 compatible 改为 `"smartisan,odin-display"`，重新构建并刷写 lk2nd。

### 🟡 问题 2【中等】fusb301 吞掉 EPROBE_DEFER → host 模式可能永久失效

**位置**：`linux-msm8953/drivers/usb/typec/fusb301.c:339–346`

```c
connector = device_get_named_child_node(dev, "connector");
if (connector)
    chip->role_sw = fwnode_usb_role_switch_get(connector);
if (IS_ERR_OR_NULL(chip->role_sw)) {
    dev_warn(dev, "no USB role switch available yet\n");
    chip->role_sw = NULL;          /* ← 错误被吞掉 */
}
```

**场景**：I2C 设备探测先于 dwc3 平台设备完成时（i2c_qup 与 dwc3-qcom 探测顺序无保证），`fwnode_usb_role_switch_get()` 返回 `-EPROBE_DEFER`，但驱动仅告警后置 NULL 且不再重试。

**后果**：CC 插入检测正常、VBUS boost 可输出 5V，但 dwc3 角色永不切换到 HOST → xHCI 不加载 → U 盘不枚举。表现为"能供电、读不到盘"。

**修复建议**：
```c
chip->role_sw = fwnode_usb_role_switch_get(connector);
if (PTR_ERR(chip->role_sw) == -EPROBE_DEFER)
    return dev_err_probe(dev, -EPROBE_DEFER,
                         "usb role switch not ready\n");
if (IS_ERR_OR_NULL(chip->role_sw))
    chip->role_sw = NULL;
```

### 🟢 问题 3【次要】息屏序列在高速模式发送 display_off/sleep_out

**位置**：三个面板驱动各 `_off()` 函数开头（如 `panel-r69006.c:150`、`panel-ft8716.c:278,542`）

```c
dsi->mode_flags &= ~MIPI_DSI_MODE_LPM;   /* 先清 LPM → HS 发送 */
ret = mipi_dsi_dcs_set_display_off(dsi);
```

与生成器参考输出一致，故不算移植偏差；但下游 MDSS 在 LP 模式发送息屏指令。若实测出现息屏失败/唤醒异常，可将清 LPM 移至 sleep_out 之后。

### 🟢 问题 4【提示】配套事项

1. `bin/lk2nd.img` 时间戳早于补丁文件约 2 分钟——经 strings 验证内容已包含 odin 面板表（当前无实质影响），后续任何补丁改动务必重新构建固件。
2. 最小化 OTG 稳压器驱动未实现下游的 OTG 过流监测 / pulse-skip / usb_suspend 投票（`refs/smbchg.c:4032`）；首测建议用带独立供电的 hub。
3. 目标系统未安装 udisks2，自动挂载仍为缺口（README 第六节已记录）。
4. FTS 触摸屏、QMP SuperSpeed PHY 未包含（README 已知限制，非本次范围）。
