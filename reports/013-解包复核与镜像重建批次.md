## 三、发现的问题

### P0-1 根分区扩容链路整条失效

- 镜像内存在 `/var/lib/odin-resize-done`（8/27 16:28，0 字节），且 `odin-firstboot-resize.service`
  **不在** `multi-user.target.wants` ⇒ 服务既未启用、又被 `ConditionPathExists=` 跳过 ⇒
  真机上根永远停在 **2 GiB**。
- 即使清掉标记也过不去：`s_reserved_gdt_blocks=0`、`compat` 无 `resize_inode`。
  内核 `fs/ext4/resize.c:1733`（`ext4_group_add`）：

  ```c
  if (reserved_gdb || gdb_off == 0) {
      if (!ext4_has_feature_resize_inode(sb) || !le16_to_cpu(es->s_reserved_gdt_blocks)) {
          ext4_warning(sb, "No reserved GDT blocks, can't resize");
          return -EPERM;
      }
  ```

  本镜像 64bit 关闭 ⇒ `desc_size=32` ⇒ `DESC_PER_BLOCK=128` ⇒ **加到第 128 组（16 GiB）处
  `gdb_off=0` 必触发 EPERM**。在线扩容会在 ~16GiB 中止，`resize2fs` 非 0 ⇒ 旧 unit 的
  `systemctl disable` 不执行 ⇒ 每次开机都挂一个 failed 单元。
- 根因：reports/011 第 9 章的重建配方把 `resize_inode` 一并关了；而 lk2nd 根本不检查 compat
  ——这一项**只有代价没有收益**。

### P0-2 NetworkManager 会接管 usb0，切断 USB 救援通道

- `NetworkManager.conf` 是 Debian 默认 `[ifupdown] managed=false`，但镜像里
  **`/etc/network/interfaces` 不存在** ⇒ 该保护落空 ⇒ NM 会把 usb0 当普通以太网自动连接、
  清掉 `172.16.42.1` ⇒ PC 拿不到 IP、SSH 失联；而屏幕在真机上从未验证过 ⇒ **只剩 UART**。
- 由最近一个"安装 NetworkManager"的提交引入，之后没有任何复验与报告。

### P1 文件系统元数据不一致（镜像疑似在挂载状态下被复制）

- `e2fsck -fn`：Free blocks count wrong（340659 vs 322459）、Free inodes count wrong
  （106467 vs 102764）。Pass 1–4 无错，数据本身完整，但超级块比位图多算约 18K 块 / 3.7K inode；
  自定义 initramfs 不跑 fsck，systemd 也不 fsck 已挂载的根 ⇒ 会长期残留。
- 佐证：`Last mounted on /mnt/dist`、镜像内残留 `/mnt/dist` 空目录、`/var/log/journal/<machine-id>/`、
  wtmp/lastlog 有登录记录。旁证：重建后文件数为 16010，而旧镜像仅统计到 12317，
  差值 3693 与"free inodes 差 3703"吻合 —— 正是挂载态复制的指纹。

### P1 身份残留

`/etc/machine-id = b88f9104c87d482cbe06d76a5b6276f6`（非空）、`/var/lib/systemd/random-seed`
存在、journal/wtmp/lastlog 有内容。

### P2 其它

`/boot` 游离 dtb；模块树缺 `kernel/` 层级而 `modules.builtin` 用 `kernel/` 前缀；
`NetworkManager-wait-online.service` 被启用；ModemManager 被顺带启用；
`FLASH.md` 尺寸与"lk2nd 解析 ext4"表述过时；`README` §二与 reports/010 结论冲突；
容器 `/mnt/img/odin-debian.img` 为 8/23 陈旧副本。

### 附带发现：容器 staging 早已不是真源

`/mnt/debian` 与 `/mnt/debian-qemu` 都停在 8/23（**无 NetworkManager**），而镜像里有 ⇒
最近几版镜像是"挂载镜像就地 apt/修改"出来的。**直接拿 `/mnt/debian` 重建镜像会丢失改动**，
这一点已写进 `FLASH.md` §七。

## 四、修复实施

| 修复 | 做法 |
|---|---|
| 扩容链路 | 清标记；重写 `odin-firstboot-resize.sh`（日志 + 不再以退出码决定自禁用）与 unit（`TimeoutStartSec=300`，无论成败都 `disable` + `touch` + `exit 0`）；重新 enable |
| 扩容能力 | 重建文件系统时显式 `-O resize_inode,^extents,^64bit,^metadata_csum,^huge_file,^dir_nlink,^extra_isize` ⇒ 实测 `s_reserved_gdt_blocks=127` |
| USB 救援通道 | 新增 `/etc/NetworkManager/conf.d/99-odin-usb0.conf`（`[keyfile] unmanaged-devices=interface-name:usb0`）；disable `NetworkManager-wait-online`、mask `ModemManager` |
| 可复现管线 | 新增 `tools/build-image.sh`：干净化 → 模块树归一 → mke2fs(保守特性集) → e2fsck → img2simg → 逐项回读校验，任一失败非零退出 |
| 增量修复脚本 | 新增 `dist/build/apply-staging-fixes.sh`（幂等、不联网、不装包），便于对既有 rootfs 打补丁 |
| 模块树 | msm8953 树搬进 `kernel/` 后 `depmod -b` 重生成；与 `modules.builtin` 的 `kernel/` 前缀统一 |
| 产物卫生 | 清 `/mnt/dist`、`/boot` 游离 dtb；machine-id / **/var/lib/dbus/machine-id** / random-seed / journal / wtmp / lastlog 全部清空 |
| 源脚本同步 | `dist/build/setup-rootfs.sh` 同步上述修复并改为幂等（useradd 已存在则跳过） |

> 踩坑记录：只清空 `/etc/machine-id` **无效** —— 实测 systemd 会从 `/var/lib/dbus/machine-id`
> 回填旧值。两个都必须清。

## 七、遗留风险（待真机确认）

1. `odin-usb-gadget.service` 依赖真机 UDC，QEMU 无法验证（本环境无 UDC，服务被 mask）。
   **首刷后 USB 网卡/SSH 是首先要确认的通道**——若不通，NM 的 unmanaged 配置与 gadget 脚本
   是第一排查对象。
2. 原厂 aboot 是否确实透传 `mdss_mdp.panel=`（reports/010 §七），需在真机查 `/proc/cmdline`
   或 `fastboot getvar lk2nd:panel`。
3. lk2nd 的 ext2 驱动对 `flex_bg` + 256 字节 inode 的实读未经真机验证（驱动按组描述符
   显式字段寻址，判定低风险）。
4. 在线扩容 2GiB → ~27GB 是 IO 密集操作，`TimeoutStartSec=300` 为估值，真机若超时需调大。
5. 触摸屏仍未移植；QMP SuperSpeed PHY 主线无支持（USB2 480Mbps）。
