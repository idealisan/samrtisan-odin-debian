## 〇、先读这一段：三句话结论

1. **这台机器跑的是"通用 msm8953 镜像 + 回落 DTB"，不是本机专属移植。** lk2nd 的 QCDT 表里没有本机条目，最终加载的是 `/boot/msm8953-xiaomi-markw.dtb`（Xiaomi Redmi 4 Prime）。但实机是 **4 GB RAM + 128 GB eMMC**，与 markw 公开规格（3 GB / 32 GB）不符 —— 说明 markw 只是"碰巧被选中"的回落 DTB，本机的屏幕、触摸、相机传感器因此全部不匹配。
2. **从 lk2nd 起的启动链是完整可跑的**，共 9 跳：`aboot → boot 分区的 lk2nd.img → 扫描分区找 /extlinux/extlinux.conf → 加载 vmlinuz+initramfs+DTB → 内核 → initramfs stage1 → stage2 → switch_root → systemd`。本机已实测走通，代价是 kernel 24.3 s + 用户态 1 min 36.7 s。
3. **目前真正不可用的外围是：显示（无 panel 驱动）、触摸（内核无 FTS 驱动）、相机（传感器模块未绑定）、光/地磁传感器（模块未绑定）。** 基带/Modem、Wi-Fi、蓝牙、音频编解码、振动、按键、充电、USB 网络（SSH 救援通道）**都是好的**。

### 1.1 关于"它到底是不是 markw"

**不是。** 三条硬证据：

| 证据 | 实机 | markw 公开规格 |
|---|---|---|
| eMMC 容量 | Samsung DJNB4R，116.5 GiB（128 GB 级），2017-03 产 | 32 GB |
| 内存 | 3.75 GiB（4 GB 器件） | 3 GB |
| 触摸芯片 | 探测不到任何触摸设备 | markw 有触摸且主线 DTB 带节点 |

lk2nd 之所以选中 markw，是因为它自带的 QCDT 表**只有 20 个设备条目，不含本机**（详见 §4.2）。所以下面所有"显示/触摸/相机不工作"的现象，**根因都是 DTB 回落错机型**，而不是硬件损坏。

### 1.2 板级 ID（lk2nd 写入）

```
qcom,msm-id   = 00 00 01 25 00 00 00 00   → <0x125 0>  (293 = MSM8953)
qcom,board-id = 00 01 00 0b 00 00 00 01   → <0x0001000b 0x00000001>
```

`qcom,board-id` 由 lk2nd 按 QCDT 匹配结果改写（lk2nd 源码里有 `qcom,board-id in device tree is (%d) not a multiple of (%d)` 的报错串，见 `evidence/device-probe/lk2nd.img` 的 strings）。移植新设备时，**新 DTB 里的 `qcom,msm-id` / `qcom,board-id` 必须与这里一致**，否则 lk2nd 不会选中它。

### 2.3 存储

**eMMC**：Samsung `DJNB4R`，manfid `0x15`，OEM `0x0100`，fwrev `0x07`，hwrev `0x0`，serial `0x<emmc-serial>`，生产 2017-03，容量 122 138 624 KiB（116.5 GiB），life_time `0x05 0x05`，erase 512 KiB / preferred 4 MiB。

**控制器**：`sdhci_msm` 两个 —— `7824900.mmc`（eMMC，mmc0/mmcblk1）+ `7864900.mmc`（**SD 卡槽，当前无卡**）。

**出厂 GPT（57 个分区，实机读出，未做任何重分区）**：

| 分区 | 起始扇区 | 大小 | pmOS 链路中的角色 |
|---|---|---|---|
| sbl1 / sbl1bak | 52 / 1076 | 512 KiB | 高通二级引导，不可动 |
| aboot / abootbak | 393216 / 395264 | 1 MiB | **原厂 LK，保留原样** |
| **boot** | 397312 | **64 MiB** | ← **lk2nd.img 刷在这里** |
| recovery | 528384 | 64 MiB | 未使用 |
| splash | 262144 | 11 MiB | 开机画面（原厂） |
| persist | 786432 | 32 MiB (ext4) | msm-firmware-loader 只读挂载 |
| modem | 2375680 | 96 MiB (vfat) | 基带固件，msm-firmware-loader 只读挂载 |
| cache | 2621440 | 256 MiB (ext4) | 空闲 |
| dsp | 79924 | 16 MiB (ext4) | ADSP 固件，msm-firmware-loader 只读挂载 |
| system | 3145728 | 3 GiB (ext4) | 弃用（残留 Android 空文件系统） |
| **userdata** | 9568256 | **111.9 GiB** | ← 整个 pmOS 盘镜像刷在这里 |

**userdata 内嵌的第二层分区表**（关键机制）：

```
userdata (mmcblk1p57)
├─ p1  pmOS_boot  243 MiB  ext2  → /boot
└─ p2  pmOS_root  111.7 GiB ext4 → /
```

- 内核**不**原生创建这些子分区节点（`/dev/mmcblk1p57p1` 不存在）
- 实际由 **kpartx（device-mapper 线性映射）** 生成：
  ```
  mmcblk1p57p1: 0 497664    linear 259:25 2048
  mmcblk1p57p2: 0 234209247 linear 259:25 499712
  ```
- 用户态看到的是 `/dev/mapper/mmcblk1p57p1` 与 `/dev/mapper/mmcblk1p57p2`
- kpartx 二进制在 initramfs 里就有（`/sbin/kpartx`），这是启动链能成立的前提之一

## 三、启动流程（从 lk2nd 起，逐步还原）

### 3.0 全景图

```
┌ 第 0 级  SoC ROM → sbl1(p3) → 原厂 aboot(p19)
│          （出厂固件，不改动）
│
├ 第 1 级  aboot 按 Android boot.img 格式读 boot 分区(p21)
│          boot 分区内容 == /boot/lk2nd.img（md5 4cf0808575b4eb44d31412f66421f068）
│          └─ "内核"载荷其实就是 lk2nd 本体 + 附加的 QCDT 设备树表
│
├ 第 2 级  lk2nd 21.0-r0 (project = lk2nd-msm8953)
│          ① 枚举 eMMC 分区，并对每个分区再解析"分区里的分区表"
│             → 发现 userdata(p57) 内的 pmOS_boot / pmOS_root
│          ② 逐个尝试 ext2 挂载，找 /extlinux/extlinux.conf
│          ③ 注入/改写 DTB：chosen/lk2nd,project、chosen/lk2nd,version、
│             chosen/bootargs、chosen/linux,initrd-start|end、
│             chosen/framebuffer@90001000（simple-framebuffer 1080x1920）、
│             根属性 qcom,msm-id / qcom,board-id
│
├ 第 3 级  extlinux.conf（在 pmOS_boot 里）
│          kernel /vmlinuz   initrd /initramfs   fdtdir /
│          append "quiet loglevel=2 pmos_boot_uuid=… pmos_root_uuid=… pmos_rootfsopts=defaults"
│          → 加载 DTB：/msm8953-xiaomi-markw.dtb（本机无专属 DTB，回落到 markw）
│
├ 第 4 级  Linux 6.17.7-msm8953 启动（约 24.3 s）
│
├ 第 5 级  initramfs stage1（/init，busybox ash，postmarketos-initramfs 3.8.9-r0）
│
├ 第 6 级  initramfs stage2（/init_2nd.sh）
│
├ 第 7 级  switch_root → /sbin/init（systemd）
│
└ 第 8 级  systemd → graphical.target（默认）
```

### 3.1 第 1 级：boot 分区里是 lk2nd，不是内核

```
$ dd if=/dev/mmcblk1p21 bs=1 count=48 | xxd
41 4e 44 52 4f 49 44 21   "ANDROID!"
3c 2d 05 00               kernel_size  = 339260
00 80 00 80               kernel_addr  = 0x80008000
01 00 00 00               ramdisk_size = 1
00 00 00 81               ramdisk_addr = 0x81000000
00 00 00 00               second_size  = 0
00 00 f0 80               second_addr  = 0x80f00000
00 01 00 80               tags_addr    = 0x80000100
00 08 00 00               page_size    = 2048
```

- 前 344080 字节与 `/boot/lk2nd.img` **md5 完全一致** → lk2nd 就刷在 `boot` 分区，`aboot` 分区保持原厂
- `ramdisk_size = 1` 说明这个 boot.img 不是用来直接起 Linux 的，lk2nd 只是借壳
- 339260 字节的"内核"载荷 = lk2nd 二进制 **+ 附加的 QCDT 设备树表**

### 3.2 第 2 级：lk2nd 的 QCDT 表（为什么选中 markw）

`lk2nd.img` 里能 strings 出 20 个设备条目：

```
apq8053-lenovo-cd-18781y   msm8953-asus-zenfone3      msm8953-billion-rimob
msm8953-huawei-cannes      msm8953-huawei-milan       msm8953-lenovo-kuntao
msm8953-motorola-sanders   msm8953-mtp                msm8953-oppo-r9s
msm8953-qrd                msm8953-xiaomi-common      msm8953-xiaomi-daisy
msm8953-xiaomi-markw       msm8953-xiaomi-oxygen      msm8953-xiaomi-vince
sdm450-samsung-r04         sdm450-samsung-r05         sdm450-xiaomi-rosy
sdm632-motorola-ocean      sdm632-mtp
```

**没有本机条目。** 于是 lk2nd 落到某个 Xiaomi msm8953 条目上，最终从 `fdtdir /`（即 pmOS_boot 根）加载了 `/msm8953-xiaomi-markw.dtb`。

lk2nd 用到的匹配/注入属性（strings 实锤）：`lk2nd,dtb-files`、`lk2nd,match-bootloader`、`lk2nd,match-cmdline`、`lk2nd,match-device`、`lk2nd,match-machtype`、`lk2nd,match-panel`、`lk2nd,panel`、`lk2nd,project`、`lk2nd,version`、`lk2nd,menu-key-strings`、`lk2nd,single-key-navigation`、`lk2nd,code`、`lk2nd,gpio`。

> **移植提示 C**：要让新 DTB 被选中，最稳的做法是**重新构建含本机条目的 lk2nd**（条目里给出 `lk2nd,dtb-files` 指向新 DTB 的文件名），而不是指望 QCDT 兜底。兜底是不可控的 —— 这次它就兜到了 markw。

### 3.3 第 3 级：extlinux.conf

`/boot/extlinux/extlinux.conf`（完整内容）：

```
timeout 1
default postmarketOS
menu title boot prev kernel

label postmarketOS
	kernel /vmlinuz
	fdtdir /
	initrd /initramfs
	append quiet loglevel=2  pmos_boot_uuid=fc55a496-dbb8-4e08-a2ce-369102ed4f15 pmos_root_uuid=a5513363-8a7f-4b04-9df4-50fc6d89a172 pmos_rootfsopts=defaults
```

- `/boot` = pmOS_boot（ext2，243 MiB，已用 58.8 MiB / 剩余 156.8 MiB）
- `fdtdir /` → DTB 从 boot 分区**根目录**找（所以 `deviceinfo_dtb` 列出的那些 DTB 都被 boot-deploy 拷到了 `/boot/` 顶层）
- 三个 `pmos_*` 参数是 initramfs 找根分区的依据

对应的 `deviceinfo`（`/usr/share/deviceinfo/deviceinfo`）：

```
deviceinfo_codename="qcom-msm8953"
deviceinfo_kernel_cmdline="quiet loglevel=2"
deviceinfo_partition_type="msdos"
deviceinfo_dtb="qcom/apq8053-* qcom/msm8953-* qcom/sdm450-* qcom/sdm632-*"
deviceinfo_generate_extlinux_config="true"
deviceinfo_boot_filesystem="ext2"
deviceinfo_external_storage="true"
```

（`/etc/deviceinfo` 全是注释，无任何覆盖。）

### 3.4 第 4 级：内核启动

内核看到的 cmdline（与 extlinux 的 append 一字不差）：

```
quiet loglevel=2  pmos_boot_uuid=fc55a496-… pmos_root_uuid=a5513363-… pmos_rootfsopts=defaults
```

三个 `pmos_*` 内核不认识，会打印 `Unknown kernel command line parameters … will be passed to user space`，由 initramfs 消费。

**注意：`loglevel=2` 把绝大多数驱动 probe 日志（pr_info）都屏蔽了**，这也是为什么 `dmesg` 里几乎看不到 USB/DSI/相机等子系统的初始化过程。调试新移植时务必先把它改成 `loglevel=7`。

关键启动事实：
- 8 核全部在 EL1 起来，PSCI v1.0
- `Machine model: Xiaomi Redmi 4 Prime`（回落 DTB 的直接体现）
- 13 个 reserved-memory 节点按 DT 建好
- devtmpfs 起来后，kpartx 才有设备可操作

### 3.5 第 5 级：initramfs stage1（`/init`）

initramfs 是 gzip 压缩的 cpio（`1f 8b 08 …`），已解包到 `evidence/device-probe/initramfs-root/`。`/init` 是 busybox ash 脚本，`INITRAMFS_PKG_VERSION="3.8.9-r0"`，执行顺序：

```
mount_proc_sys_dev          # 挂 proc/sys/dev
parse_cmdline < /proc/cmdline
setup_log                   # 输出 "❬❬ PMOS STAGE 1 ❭❭"
setup_firmware_path
jump_init_2nd               # 若 /init_2nd.sh 存在就先跳（这里存在，所以 stage1 只跑一遍 setup_usb_network）
setup_mdev                  # 装 mdev，为了先找到 boot 分区
load_modules /lib/modules/initramfs.load     # 本机该文件为空
setup_usb_network           # ★ 配 USB gadget
start_unudhcpd              # ★ 起 DHCP
setup_framebuffer + show_splash "Loading..."
mount_subpartitions         # ★ kpartx -afs 解析嵌套 GPT
wait_boot_partition
mount_boot_partition /boot
extract_initramfs_extra /boot/initramfs-extra   # 本机没有 extra
umount /boot
kill mdev
jump_init_2nd
```

里面带的工具（就是这些决定了它能做到什么）：
`busybox`、`busybox-extras`、`kmod`、`udevadm`、`udevd`、`unudhcpd`、`pbsplash`、`iskey`、`buffyboard`、`blkid`、`dmsetup`、`kpartx`、`parted`、`e2fsck`、`resize2fs`、`fsck.vfat`、`fsck.f2fs`、`resize.f2fs`、`switch_root`。

**`mount_subpartitions` 的实现（关键，逐字引用）**：

```sh
try_parts="/dev/disk/by-partlabel/userdata /dev/disk/by-partlabel/system* /dev/mapper/system*"
find_root_partition
while [ -z "$PMOS_ROOT" ]; do
    partitions="$android_parts $(grep -v "loop\|ram" < /proc/diskstats | sed 's/\(\s\+[0-9]\+\)\+\s\+//;s/ .*//;s/^/\/dev\//')"
    for partition in $partitions; do
        [ -e "/sys/class/block/$(basename "$partition")/partition" ] || continue
        case "$(kpartx -l "$partition" 2>/dev/null | wc -l)" in
            2)  echo "Mount subpartitions of $partition"
                SUBPARTITION_DEV="$partition"
                kpartx -afs "$partition"
                find_root_partition
                [ -n "$PMOS_ROOT" ] && break
                kpartx -d "$partition"; SUBPARTITION_DEV=""; continue ;;
        esac
    done
    …最多等 10 秒…
done
```

即：**只接受"恰好有 2 个子分区"的分区**，用 `kpartx -afs` 建立映射，然后按 UUID/标签 `pmOS_root` 校验，不对就 `kpartx -d` 撤销。这就是 §2.3 那两个 linear 映射的由来。

### 3.6 第 6 级：initramfs stage2（`/init_2nd.sh`）

```
setup_udev                          # 由 mdev 换成 udevd（为了早加载显示驱动）
setup_usb_network / start_unudhcpd  # 幂等，stage1 已跑过则跳过
[非 extra 模式] setup_framebuffer + show_splash "Loading..."
setup_dynamic_partitions ""         # 无 super 分区，空转
run_hooks /hooks
[debug_shell=y?] debug_shell
check_keys                          # 实体键组合（iskey）
mount_subpartitions                 # 幂等
run_hooks /hooks-extra
wait_root_partition
delete_old_install_partition
resize_root_partition
unlock_root_partition               # 本机无 LUKS（无 /etc/crypttab），空转
resize_root_filesystem
mount_root_partition                # 挂到 /sysroot
resize_filesystem_after_mount /sysroot
[若 /sysroot/etc/fstab 为空] → wait_boot_partition + mount_boot_partition /sysroot/boot
init=/sbin/init
setup_bootchart2
run_hooks /hooks-cleanup
show_splash "Starting..."
killall udevd syslogd ; 杀掉多余 sh
rm /dev/log
exec switch_root /sysroot /sbin/init
```

### 3.7 USB 网络（SSH 救援通道）是怎么搭起来的

`setup_usb_network_configfs()`：

1. `modprobe libcomposite`
2. `mkdir /sys/kernel/config/usb_gadget/g1`，写 `idVendor=0x18D1` / `idProduct=0xD001`（Google / Nexus 4 fastboot 默认值，deviceinfo 未覆盖）
3. 建 `strings/0x409`，写 manufacturer = `deviceinfo_manufacturer`、product = `deviceinfo_name`、serialnumber = `postmarketOS`
4. `mkdir functions/ncm.usb0`（失败则回落 `rndis.usb0`）
5. `mkdir configs/c.1` + `strings/0x409`，配置名写 "USB network"，把 function 软链进配置
6. `setup_usb_configfs_udc()`：先清空 UDC 再写回（避免 `Resource busy`），UDC 名字取 `ls /sys/class/udc | head -1`
7. `start_unudhcpd()`：`ifconfig usb0 172.16.42.1` 然后 `unudhcpd -i usb0 -s 172.16.42.1 -c 172.16.42.2 &`

实测结果：`/sys/class/udc/7000000.usb`，`g1/UDC = 7000000.usb`，`functions/ncm.usb0`，`usb0` 上 `172.16.42.1/16`，`unudhcpd -i usb0 -s 172.16.42.1 -c 172.16.42.2` 在跑。

> **移植提示 D**：这套逻辑是"开机那一刻定生死"的 —— 若那一刻 `/sys/class/udc` 为空（比如 CC 判定成 host），`setup_usb_network_configfs` 会打印 "No UDC found, skipping gadget setup..." 并直接返回，**之后再插线也不会重试**。新移植若引入 USB 角色切换，必须配套 udev 规则或轮询守护来重配 gadget。

### 3.8 第 7–8 级：systemd

- 根挂载：`/dev/mapper/mmcblk1p57p2 → /`（ext4），`/dev/mapper/mmcblk1p57p1 → /boot`（ext2, nodev,nosuid,noexec）
- `/etc/fstab` 用 UUID（无 crypttab，未加密）
- 默认 target：`graphical.target`（尽管装的是 console UI）
- 关键服务：`systemd-udevd`、`NetworkManager`、`iwd`、`rmtfs`、`tqftpserv`、`msm-firmware-loader`、`postmarketos-zram-swap`、`docker`、`containerd`、`incus`、`chrony`、`sshd`、`tinyproxy`、`dbus`、`polkit`
- 已启用服务中值得注意的：`msm-firmware-loader` 把 modem/dsp/persist 三个分区只读挂到 `/run/msm-firmware-loader/mnt/`

### 3.9 启动链上"必须对齐"的 8 个约定

| # | 衔接 | 依赖的约定 |
|---|---|---|
| 1 | aboot → lk2nd | lk2nd 必须是合法 Android boot.img（"内核"=lk2nd 本体） |
| 2 | lk2nd → pmOS_boot | userdata 内的镜像自带子 GPT，且**恰好 2 个子分区**，`pmOS_boot`/`pmOS_root` 标签固定 |
| 3 | lk2nd 找到配置 | 约定路径 `/extlinux/extlinux.conf`，且 `deviceinfo_generate_extlinux_config="true"` 才会生成 |
| 4 | DTB 文件名 | `fdtdir /` + lk2nd 设备条目里的 `lk2nd,dtb-files`，必须与 `/boot/<name>.dtb` 同名 |
| 5 | DTB 被选中 | 新 DTB 的 `qcom,msm-id` / `qcom,board-id` 必须与实机一致（`293` / `<0x0001000b 0x1>`） |
| 6 | initramfs → 子分区 | 靠 **kpartx**（不是内核原生嵌套分区！），initramfs 里必须带 `kpartx` + `dmsetup` |
| 7 | initramfs → root | cmdline `pmos_root_uuid=` 优先，否则 `blkid --label pmOS_root` 全盘扫 |
| 8 | rootfs 自洽 | device 包 depends 拉齐 内核/lk2nd/固件/soc 包；apk 触发器装完即生成 initramfs + extlinux.conf，保证 `/boot` 三件套同版本 |

## 四、移植时要特别注意的坑（本次实测新发现）

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **没有本机 DTB，回落到 markw** | lk2nd QCDT 20 条无本机；`/proc/device-tree/model = Xiaomi Redmi 4 Prime` | 屏幕/触摸/相机全线不匹配 |
| 2 | **panel 驱动不存在** | `panel@0` compatible = `xiaomi,markw-panel`，70+ 个 `DRM_PANEL_*` 里没有它 | 无 `/dev/dri`、无 `fb0` |
| 3 | **`CONFIG_FB_SIMPLE` 未开** | `/sys/bus/platform/drivers/simple-framebuffer` 不存在；`90001000.framebuffer` 无驱动 | `gcc-msm8953: sync_state() pending due to 90001000.framebuffer` → 时钟/互连无法进入低功耗 |
| 4 | **cmdline 里没有 `mdss_mdp.panel=`** | 内核 cmdline 只有 `quiet loglevel=2 pmos_*` | 若打算走"aboot 透传面板名 → lk2nd 改写 compatible"这条路，**必须先用串口实机确认原厂 aboot 到底透不传**；当前读数是不传 |
| 5 | **内核无 FocalTech 触摸驱动** | 7 个 TOUCHSCREEN 配置里无 FTS/STMFTS | 触摸是独立移植任务 |
| 6 | **相机/光感/地磁模块加载但未绑定** | `ov5670`、`s5k2xx`、`ltr501`、`yamaha_yas530`、`leds-aw2013` 全为 `Used by 0`，`waiting_for_supplier=0` | 不是供电依赖问题，是 probe 环节没成；换 DTB 后需重查 |
| 7 | **传感器走软件 I²C** | `i2c-gpio i2c-gpio: using lines 526 (SDA) and 527 (SCL)` | 时序与上拉和硬件 I²C 不同，新 DTB 必须原样保留 i2c-gpio 节点 |
| 8 | **文件系统支持残缺** | `NTFS3_FS`/`NTFS_FS` 均未编；`exfat` 只是模块且未加载；`NLS_UTF8` 未编（exfat 默认 iocharset 就是 utf8）；vfat 默认 `iso8859-1`，且无 `cp936` | NTFS 盘完全挂不了；exFAT 需 `modprobe exfat` 且指定 `iocharset=ascii`；FAT32 中文名乱码 |
| 9 | **没有自动挂载** | 无 `udisks2` / `gvfs` / `udiskie`，`/etc/udev/rules.d/` **空目录** | OTG 接 U 盘只能手工 `mount` |
| 10 | **USB 角色被钉在 peripheral** | DT `role-switch-default-mode="peripheral"`；`/sys/class/usb_role/7000000.usb-role-switch/` 下**无 `role` 文件**（`find /sys -name role` 为空） | 无法 `echo host > role` 手动切；只能靠 ID 脚/CC 硬件触发 |
| 11 | **`loglevel=2` 屏蔽驱动日志** | `deviceinfo_kernel_cmdline="quiet loglevel=2"` | 调试新移植第一件事就是改回 `loglevel=7` |
| 12 | **开机被 tinyproxy 拖慢 90 秒** | `systemd-analyze blame` | 新镜像建议去掉或加超时 |
| 13 | **`/etc/udev/rules.d/` 为空** | `ls` 结果 | 任何"插拔自动响应"（UDC 重配、U 盘自动挂载）都没有落点，需要自己加规则文件 |

## 六、复现采集的命令

本机没有 `sshpass`，先 `brew install sshpass`。提权用 `doas`（opendoas 不支持 `-S`，也没有 `-S`，必须给 tty）：

```sh
# 普通命令
sshpass -p <pwd> ssh -o StrictHostKeyChecking=no user@172.16.42.1 '<cmd>'

# 需要 root 的命令（opendoas 要求 tty，必须 -tt）
scp script.sh user@172.16.42.1:/tmp/pmr.sh
expect -c 'spawn ssh -tt -o StrictHostKeyChecking=no user@172.16.42.1 "doas sh /tmp/pmr.sh 2>&1"
           expect -re "assword:" { send "<pwd>\r"; exp_continue }
           expect eof'
```

`doas` 配置：`/etc/doas.d/10-postmarketos.conf` → `permit persist keepenv :wheel`（user 在 wheel 组）。
