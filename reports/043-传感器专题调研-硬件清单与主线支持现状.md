## 一、硬件清单（原厂 DTS + 真机 i2c 扫描）

### 1.1 原厂声明的 i2c / spi 器件

| 总线 | 地址 | compatible | 是什么 | 出处 |
|---|---|---|---|---|
| i2c_3 `78b7000` (BLSP1 QUP3) | 0x38 | `focaltech,fts` | 触摸屏 | `msm8953-qrd.dtsi:45-60` |
| i2c_3 | 0x01 | `novatek,NVT-ts` | 触摸屏备选（与 FT 二选一） | `msm8953-qrd.dtsi:62-74` |
| i2c_3 | 0x29 | `tcs3400` | RGBW 色彩 + 环境光，**无 IRQ** | `msm8953-qrd.dtsi:83-87` |
| i2c_3 | 0x44 | `nxu8010` | RGBW / 色温，**无 IRQ** | `msm8953-qrd.dtsi:76-80` |
| i2c_5 `7af5000` (BLSP2 QUP1) | 0x28 | `qcom,nq-nci` | NFC（NXP NQ 系列） | `msm8953-qrd.dtsi:224-242` |
| i2c_6 `7af6000` | 0x25 | `fcs,fusb301` | Type-C CC/DRP 控制器 | 我方主线 DTS 补的 |
| spi_7 `7AF7000` (BLSP2 QUP2) | — | `goodix,fingerprint` | 指纹 GF3208 | `u3-p1-msm8953-goodix-odin.dtsi:2-25` |

i2c_2 / i2c_6 在 `*odin*` 与 `*8953-qrd*` 里除了 FUSB301 外**零引用**；spi_3 无子节点。

### 1.2 真机 i2c 扫描（决定性证据）

在真机装 `i2c-tools` 后逐总线扫描：

```
i2c-0 (= 78b7000)：只有 0x38  ← 触摸屏
i2c-1 (= 7af6000)：只有 0x25  ← FUSB301
```

**我方 DTB 只开了 2 条 i2c**，另外 6 条全是 `status=disabled`：
`7af5000`、`7af7000`、`7af8000`、`78b5000`、`78b6000`、`78b8000`。

**两个直接结论：**
1. **没扫到任何加速度 / 陀螺 / 地磁 / 光感 / 距离 / 霍尔。**
2. 但注意 —— 原厂说 i2c_3 上还有 `0x29`(tcs3400) 和 `0x44`(nxu8010)，
   我们的 i2c-0 就是 78b7000（i2c_3），**这条总线我们开着，却只扫到 0x38**
   ⇒ **这两颗芯片在这台机器上大概率没焊**（或没供电）。

### 1.3 真机现状

| 项 | 值 |
|---|---|
| IIO 设备 | 只有 2 个 PMIC ADC：`200f000.spmi:pmic@0:adc@3100`、`pmic@2:adc@3100`（电压/电流/温度），**没有真正的运动传感器** |
| LED | `/sys/class/leds/` 只有 `mmc0::`、`mmc1::` ⇒ **指示灯完全没接上** |
| input 设备 | `gpio-keys`、`pm8941_pwrkey`、`pm8941_resin`、`smartisan-odin Headset Jack` |
| remoteproc | `remoteproc0 = wcnss.mdt (running)`、`remoteproc1 = adsp.mdt (running)` |
| 传感器固件 | `/lib/firmware` 下 **没有任何 slpi / sensor / ssc 固件** |

## 二、逐项结论

### 2.1 加速度 / 陀螺 / 地磁 / 光感 / 距离 —— 原厂全在 SLPI 闭源固件里

证据：
- 原厂 DTS 只有一个**空壳**节点 `qcom,msm-ssc-sensors`（`msm8953.dtsi:2003-2005`）
- 它的"驱动" `drivers/sensors/sensors_ssc.c` **不是传感器驱动**，而是 **SLPI 固件加载器**：
  `slpi_boot_store()` + `__ATTR(boot)`，通过 sysfs 写 `boot` 触发加载
- 原厂 `msm8953.dtsi` 的 PIL 节点只有 `modem / adsp / venus / wcnss` 四个，**没有 slpi**
  ⇒ SLPI 是另一套加载机制，固件文件（`slpi.b*`/`slpi.mdt`）来自 vendor 分区
- 我们镜像里没有 SLPI 固件

**⇒ 这些传感器 AP 侧看不到，是因为它们挂在 SLPI 独占的通道上。**
主线上没有 SLPI 传感器固件可用，**不能走原厂那条路**。

主线能给的路只有一条：**确认芯片是否挂在 AP 可达的 i2c 上，是的话直接挂 IIO 驱动**。
这需要先把那 6 条 disabled 的 i2c 打开扫一遍 —— **这是本专题第一个该做的实验**。

### 2.2 环境光 / 色温 —— 硬件大概率不存在

原厂声明 `tcs3400@0x29`、`nxu8010@0x44`，都在 **i2c_3 = 78b7000** 上，
而这条总线我们开着、只扫到 0x38 ⇒ **两颗都没扫到**。
即便有，主线**两颗都没有驱动**（全树 grep 零命中）。替代 `tcs3472` 存在但配置关闭。

### 2.3 霍尔传感器 —— 原厂没有，硬件大概率不存在

grep `hall|cover|flip|lid` 于原厂 odin 与 msm8953 DTS，只有 `valid-status-check`、
`vbus-valid-override` 两处误命中。gpio_keys 只有音量/主页
（`u3-p1-msm8953-key-odin.dtsi:25-55`：vol_up 85/115、vol_down 86/114、key_home 87/102）。

### 2.4 GPS / GNSS —— 无独立芯片，只能走 WCNSS

证据：
- `arch/arm64/boot/dts/` 全目录 grep `gps|gnss` → **0 命中**
- WCNSS 节点存在（`msm8953.dtsi:1486-1566`，`qcom,is-pronto-v3`，iris 四路电 l7/l19/l9/l5，
  gpio 76-80，时钟 xo/rf_clk2/wcnss_m），但**里面没有任何 GNSS 子节点**，
  没有 LNA 使能、没有 GPS 专用 regulator / clock / pinctrl
- `smdtty`（`msm8953.dtsi:1388-1446`）枚举的口只有
  `APPS_FM / APPS_RIVA_BT_ACL / APPS_RIVA_BT_CMD / APPS_RIVA_ANT_CMD / APPS_RIVA_ANT_DATA /
   DATA1,4,11,21 / LOOPBACK` —— **没有 GPS 端口**
- defconfig 无 `CONFIG_GPS`、`CONFIG_QTI_*GNSS`

**⇒ 若硬件有 GPS，只能是 WCNSS/Pronto 里集成的 GNSS，靠 `wcnss.mdt` 固件 + 用户态
LOC/QMI 服务。我们已经在跑 `wcnss.mdt`（remoteproc0 running），所以这条路**理论上是通的**，
但需要移植/部署一套 QMI LOC 用户态服务，工作量大且依赖闭源固件行为。**

主线 `# CONFIG_GNSS is not set`，`GNSS_SIRF/MTK/SERIAL` 都不导出。

### 2.5 震动马达 —— **最现成的一项，直接可做**

原厂：`pmi_haptic` / `qcom,qpnp-haptic`，SPMI `pmi8950@3`，`reg <0xc000 0x100>`，
LRA 线性马达，`vmax-mv=2545`、`ilim-ma=80`、`wave-shape=sine`、`play-mode=buffer`
（`u3-p1-msm8953-haptics.dtsi:13-37`）。

主线对得上：
- 驱动：`drivers/input/misc/qcom-spmi-haptics.c:999` → `.compatible = "qcom,spmi-haptics"`
  （Kconfig `INPUT_QCOM_SPMI_HAPTICS`）
- 节点：**`pmi8950.dtsi:207-217` 已有 `pmi8950_haptics: haptics@c000`**，
  compatible `"qcom,pmi8950-haptics","qcom,spmi-haptics"`，`reg=<0xc000>`，
  中断 short/play，`HAP_PLAY_DIRECT`，默认 disabled
  ⇒ **和我们的硬件地址完全吻合，不用新建节点**

**缺口只有两个：**
1. `CONFIG_INPUT_QCOM_SPMI_HAPTICS` 在我们的配置里**一个匹配都没有** ⇒ 驱动不编译
   （依赖 `ARCH_QCOM=y`、`SPMI=y` 都已满足）
2. DTS 需要 `&pmi8950_haptics { status = "okay"; ... }`

主线 13 块 msm8953 板全部启用它（potter:217、milan:265、vince:212、mido:237、markw:285、
daisy:214、ysl:207、tissot:175、rimob:191），通行写法：
```
qcom,actuator-type = <HAP_TYPE_ERM>;
qcom,play-mode = <HAP_PLAY_DIRECT>;       /* potter 等另加 brake-pattern */
qcom,wave-play-rate-us = <5263>;
qcom,wave-shape = <HAP_WAVE_SQUARE>;
qcom,vmax-millivolt = <2600>;             /* 部分板子 */
status = "okay";
```
⚠️ 注意：原厂写的是 **LRA**（`actuator-type="lra"`、vmax 2545mV、wave sine），
而主线其它板子多是 **ERM**。我们这台是 LRA，参数要照原厂来，别照抄主线板子的 ERM。

### 2.6 指示灯 LED —— 两颗，一颗好做一颗难做

原厂 `u3-p1-msm8953-leds-odin.dtsi`（全文只有两个节点，无 GPIO，走 SPMI MPP/PWM）：

| 灯 | 位置 | compatible | 名字 / 触发 | 参数 |
|---|---|---|---|---|
| 绿 | `pmi8950@2` → `qcom,leds@a200` | `qcom,leds-qpnp` | `green`，`batter-full` → **充电指示（充满）** | `qcom,id=6`，max-current 40，mode manual，source-sel 1，mode-ctrl 0x10 |
| 蓝 | `pm8953@0` → `qcom,leds@a300` | `qcom,leds-qpnp` | `blue`，`none` → **通知灯（用户态控制）** | mode pwm，source-sel 0x0A，`pwms=<&pm8953_pwm 0 0>`，pwm-us 2400000，pwm-channel 0 |

无按键背光节点。

主线侧：
- **`qcom,leds-qpnp` 没有主线驱动**（原厂那个 `leds-qpnp.c` 是下游的）
- 主线 LPG 驱动 `drivers/leds/rgb/leds-qcom-lpg.c`，match 表含 **`qcom,pmi8950-pwm`**
  （行 1835），但**没有 `qcom,pm8953-pwm`** —— 蓝灯用的正是 pm8953 0xbc00 PWM
- 配置：`CONFIG_LEDS_QCOM_LPG=m` **已开**；`LEDS_GPIO`、`LEDS_PWM` **关**；
  `LEDS_AW2013=m`、`LEDS_ATC=m`、`LEDS_CLASS_FLASH=m`、`LEDS_CLASS_MULTICOLOR=m` 已开
- 主线 msm8953 做法：potter 用 `&atc_leds`（`qcom,leds-atc`，`pmi8950.dtsi:169-173`）；
  mido / markw 用 `&aw2013_led`（i2c `awinic,aw2013`@0x45）挂 `led@0/1/2`

**⇒ 绿灯（pmi8950 MPP）可以用 LPG 试；蓝灯（pm8953 PWM）主线 LPG 不匹配，
需要给 LPG 补 compatible 或换方案。**

### 2.7 NFC / 指纹（顺带记录）

- NFC：NXP `qcom,nq-nci` @ i2c_5 0x28，IRQ gpio17、VEN gpio16、FIRM gpio62、CLKREQ pm8953_gpios 2
- 指纹：Goodix GF3208，SPI gpio135-140。**两处异常**：节点挂在 `&soc` 下而非 `&spi_7` 下
  且无 `reg`；`spi_7`(7AF7000) 默认 `disabled` 且未被 odin 打开 ⇒ 驱动须自建 master。
  另外 `u3-p1-msm8953-idex-odin.dtsi:29/41/54` 与 `goodix-odin.dtsi:40/52/65`
  **重复定义**三个同名 pinctrl label（两者都被 `special-odin.dtsi` include），
  而 `CONFIG_FINGERPRINT_IDEX=n` —— 死代码但有隐患。

## 四、可行性与排队建议

| 项目 | 可行性 | 做法 | 备注 |
|---|---|---|---|
| **震动马达** | **高（近乎现成）** | ① 补 `CONFIG_INPUT_QCOM_SPMI_HAPTICS=y/m`；② DTS 加 `&pmi8950_haptics { status="okay"; }` + LRA 参数 | 主线驱动+节点都在，改两处即可。**建议第一个做** |
| **扫描隐藏 i2c** | **必做的前置** | 把 6 条 disabled 的 i2c 临时全开，扫一遍，确认芯片到底在不在 | 决定后面 IMU 类能不能做 |
| 加速度/陀螺/地磁 | 待定（取决于扫描） | 若扫到 → 挂 IIO 驱动（LSM6DSX/BMI160 已开）+ `mount-matrix`；若只在 SLPI → 主线无解 | 原厂走 SLPI，不乐观 |
| 指示灯（绿） | 中 | 试 `LEDS_QCOM_LPG`（已 =m）+ `qcom,pmi8950-pwm` 节点 | 需实测 |
| 指示灯（蓝） | 低~中 | 主线 LPG 不认 `qcom,pm8953-pwm`，需补 compatible 或换 `LEDS_PWM`（配置关着，要开） | |
| 环境光/色温 | 低 | 硬件大概率没焊（同总线只扫到触摸）；主线也无驱动 | |
| 霍尔 | 无 | 原厂没有，硬件大概率不存在 | |
| GPS | 低 | 只能走 WCNSS/Pronto 的 GNSS + 用户态 LOC/QMI，依赖闭源固件行为 | 我们已在跑 `wcnss.mdt`，理论可通但工作量大 |
| NFC / 指纹 | 低优先 | 需要对应驱动；指纹还有 DTS 结构问题 | 本轮不做 |
